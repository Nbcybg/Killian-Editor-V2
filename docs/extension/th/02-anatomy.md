## 2.1 โครงของปลั๊กอิน

```
my-plugin/                 ← ชื่อโฟลเดอร์ = ตัวตนของปลั๊กอิน
├─ plugin.json             ← บังคับ: manifest
├─ main.js                 ← ไฟล์ที่ถูกรัน (ชื่ออื่นได้ ระบุใน "entry")
├─ README.md               ← ไม่บังคับ: สำหรับคนอ่านบน GitHub
├─ LICENSE                 ← ไม่บังคับ แต่ควรมี
└─ (ไฟล์อื่น ๆ)             ← ถูกติดตั้งไปด้วย แต่โปรแกรมไม่อ่านเอง
```

โปรแกรมอ่านแค่สองไฟล์: `plugin.json` และไฟล์ที่ `entry` ชี้ ไฟล์อื่นในโฟลเดอร์ถูกคัดลอกตอนติดตั้ง แต่ **ปลั๊กอินไม่มี API อ่านไฟล์ในโฟลเดอร์ของตัวเองเมื่ออยู่ในโฟลเดอร์ของผู้ใช้** (API ไฟล์ของ `k2` จำกัดอยู่ในโฟลเดอร์ผลงาน) — ข้อมูลประกอบ (ตาราง · ข้อความ · รูปเล็ก ๆ เป็น data URL) จึงควรรวมเข้าไฟล์ entry ตอน bundle

### ชื่อโฟลเดอร์สำคัญกว่าที่คิด

ชื่อโฟลเดอร์ถูกใช้เป็น:

| ใช้เป็น | รูปแบบ |
|---|---|
| ชื่อที่ **แสดงบนการ์ด** ในแผงปลั๊กอิน | `<ชื่อโฟลเดอร์>` |
| `k2.pluginName` | `<ชื่อโฟลเดอร์>` |
| กุญแจของค่าตั้ง | `project.khn.json → settings.plugins["<ชื่อโฟลเดอร์>"]` |
| กุญแจของ "ปิดไว้" | `settings.plugins.disabled["<ชื่อโฟลเดอร์>"]` |
| ชื่อช่องคีย์ลัด | `plugin:<ชื่อโฟลเดอร์>:<id>` |
| id ของแผง | `plugin-<ชื่อโฟลเดอร์>-<id>` |
| คำนำหน้าในบันทึก | `[plugin <ชื่อโฟลเดอร์>]` |

→ **เปลี่ยนชื่อโฟลเดอร์ = ปลั๊กอินตัวใหม่** ค่าตั้งเดิมของผู้ใช้ไม่ตามมา
→ ใช้ชื่อแบบ `kebab-case` อักษรอังกฤษ: `word-count` · `scene-stamps` — ปลอดภัยกับทุกระบบไฟล์ ลิงก์ และ id ของ DOM

> **พฤติกรรมของรุ่น alpha.169**: ช่อง `name` ใน `plugin.json` ยังไม่ถูกนำไปแสดง — การ์ดในแผงแสดง **ชื่อโฟลเดอร์** ใส่ `name` ไว้เสมอ (จะถูกใช้เมื่อโปรแกรมรองรับ) แต่ตั้งชื่อโฟลเดอร์ให้อ่านรู้เรื่องด้วย

## 2.2 `plugin.json`

```json
{
  "name": "นับคำตอนบันทึก",
  "entry": "main.js",
  "version": "1.2.0",
  "author": "ชื่อคุณ",
  "description": "บอกจำนวนคำทุกครั้งที่บันทึก และมีแผงสรุป",
  "minAppVersion": "2.0.0-alpha.169",
  "homepage": "https://github.com/you/k2-word-count",
  "hotReload": true
}
```

| ช่อง | ชนิด | จำเป็น | ความหมาย |
|---|---|---|---|
| `name` | string | แนะนำ | ชื่อที่อ่านง่าย (ดูหมายเหตุข้างบน) |
| `entry` | string | ไม่ | ไฟล์ที่ถูกรัน · ค่าเริ่มต้น `main.js` · เป็นทางสัมพัทธ์ในโฟลเดอร์ปลั๊กอิน (`dist/main.js` ได้) · **ห้าม** ขึ้นต้นด้วย `/` หรือมี `..` |
| `version` | string | แนะนำ | แสดงบนการ์ด (`v1.2.0`) — ใช้ semver ([8.4](08-packaging-distribution.md#84-เลขรุ่น)) |
| `author` | string | ไม่ | แสดงบนการ์ด |
| `description` | string | แนะนำ | แสดงบนการ์ด — หนึ่งประโยคว่าปลั๊กอินทำอะไร |
| `minAppVersion` | string | **แนะนำอย่างยิ่ง** | รุ่นโปรแกรมขั้นต่ำ — ต่ำกว่านี้โปรแกรม **ไม่รัน** และการ์ดขึ้น "รุ่นไม่พอ" |
| `homepage` | string | ไม่ | ลิงก์รีโป/เอกสาร |
| `hotReload` | boolean | ไม่ | `true` = รับรองว่า `k2.onUnload` เก็บกวาดครบ → ปิด/ถอน/แก้โค้ดได้โดยไม่ต้องเริ่มโปรแกรมใหม่ ([บทที่ 4](04-hooks-lifecycle.md#hotreload--คำมั่นของผู้เขียน)) · ต้องเป็น `true` จริง ๆ (ไม่ใช่ `"true"`) |

กติกา:

- ต้องเป็น **JSON object ที่อ่านได้** — อ่านไม่ออก / เป็นอาร์เรย์ / ไม่ใช่ object = ปลั๊กอินถูกนับว่าพัง และถูกปิดอัตโนมัติ
- ช่องที่โปรแกรมไม่รู้จักถูกมองข้าม (ใส่ช่องของคุณเองได้ เช่น `repository` `license` `keywords` — ดู [9.4](09-store-submission.md#94-manifest-ที่พร้อมสำหรับรายการแนะนำ))
- บันทึกเป็น UTF-8

### การเทียบ `minAppVersion`

โปรแกรมเทียบ **เฉพาะตัวเลขก่อนเครื่องหมาย `-`** ทีละส่วน:

| รุ่นโปรแกรม | `minAppVersion` | รันไหม |
|---|---|---|
| `2.0.0-alpha.169` | `2.0.0-alpha.169` | ✔ |
| `2.0.0-alpha.169` | `2.0.0-alpha.200` | ✔ ⚠ (ส่วน `-alpha.N` ไม่ถูกเทียบ) |
| `2.0.0-alpha.169` | `2.1.0` | ✘ รุ่นไม่พอ |
| `2.1.0` | `2.0.5` | ✔ |

> ในช่วง alpha ทุกรุ่นเป็น `2.0.0-alpha.N` — `minAppVersion` จึง **ยังกันรุ่น alpha ที่เก่ากว่าไม่ได้** ถ้าปลั๊กอินพึ่ง API ที่เพิ่งมี ให้ตรวจตอนรันด้วย:
>
> ```js
> const alpha = Number((k2.appVersion.match(/alpha\.(\d+)/) || [])[1] || Infinity);
> if (alpha < 169 || typeof k2.onUnload !== 'function') {
>   k2.setStatus('ปลั๊กอินนี้ต้องใช้ Killian 2 alpha.169 ขึ้นไป');
>   throw new Error('needs alpha.169+');      // โยน error = ปลั๊กอินถูกปิด ไม่ทำงานครึ่ง ๆ กลาง ๆ
> }
> ```

## 2.3 ที่อยู่ของปลั๊กอิน

| | โฟลเดอร์ของ **ผู้ใช้** | โฟลเดอร์ของ **ผลงาน** |
|---|---|---|
| ที่อยู่ | `<ข้อมูลผู้ใช้>/Plugins/<ชื่อ>/` | `<ผลงาน>/Plugins/<ชื่อ>/` |
| ใช้ได้กับ | ทุกผลงานบนเครื่องนี้ | ผลงานนั้น — ก๊อป/ซิปผลงานแล้วปลั๊กอินไปด้วย |
| ต้องให้ผู้ใช้อนุญาตก่อนรัน | ไม่ (ผู้ใช้ติดตั้งเองกับมือ) | **ใช่** และต้องอนุญาตใหม่ทุกครั้งที่ไฟล์ในชุดเปลี่ยน ([บทที่ 7](07-security.md#73-การอนุญาตปลั๊กอินของผลงาน)) |
| "ติดตั้งจากลิงก์" ลงที่นี่ | ✔ เสมอ | — |
| เหมาะกับ | เครื่องมือทั่วไป · การพัฒนา | เครื่องมือเฉพาะของผลงาน/ทีม |

`<ข้อมูลผู้ใช้>`: Windows `%APPDATA%\Killian 2\` · macOS `~/Library/Application Support/Killian 2/` · Linux `~/.config/Killian 2/`

- **ชื่อซ้ำกันสองที่ → ของผลงานชนะ** และของผู้ใช้ชื่อนั้น **ไม่ถูกรันเลย** (การ์ดขึ้นป้าย "มีชื่อซ้ำ")
- โฟลเดอร์ `Plugins/dictionaries/` สงวนไว้ให้คลังคำของตัวตรวจคำผิด — ไม่ใช่ปลั๊กอิน
- โปรแกรมดูเฉพาะ **โฟลเดอร์ชั้นแรก** ใต้ `Plugins/` (ไม่ลงไปหาในโฟลเดอร์ซ้อน)

## 2.4 โปรแกรมโหลดปลั๊กอินยังไง

ตัวโหลดทำงานเมื่อ **เปิดผลงาน** และเมื่อผู้ใช้กด **โหลดใหม่ / เปิดใช้ / ปิด / ติดตั้ง / ถอน** ในแผงปลั๊กอิน ทีละรอบ ไม่ซ้อนกัน:

```
1. อ่านของบนดิสก์
   ├─ โฟลเดอร์ของผู้ใช้  → รายชื่อโฟลเดอร์ → อ่าน plugin.json + ไฟล์ entry ของทุกตัว
   └─ โฟลเดอร์ของผลงาน → เหมือนกัน + คำนวณ "ลายนิ้วมือ" ของทั้งชุด
        └─ ยังไม่ได้รับอนุญาต → ทุกตัวในชุดเป็น "รออนุญาต" และไม่ถูกรัน

2. คัดว่า "ตัวไหนควรทำงาน"
   ├─ ผู้ใช้ปิดไว้            → ข้าม (ปิดอยู่)
   ├─ plugin.json อ่านไม่ออก → พัง → ปิดอัตโนมัติ
   ├─ รุ่นโปรแกรมไม่ถึง       → ข้าม (รุ่นไม่พอ)
   └─ ชื่อซ้ำ                → ของผลงานทับของผู้ใช้

3. เทียบกับตัวที่กำลังทำงานอยู่ (ด้วยกุญแจ = ที่มา + plugin.json + โค้ด)
   ├─ เหมือนเดิมทุกตัวอักษร → ปล่อยให้ทำงานต่อ ไม่รันซ้ำ
   ├─ เปลี่ยน / หายไป / ถูกปิด → ถอดของเก่าออก (เรียก onUnload → ถอนของที่ลงทะเบียน)
   └─ ตัวใหม่ + ตัวที่เปลี่ยน → รัน

4. รัน:  new Function('k2', <เนื้อไฟล์ entry>)(k2)
   └─ โยน error → ถอดของที่ลงทะเบียนไปแล้ว → ปิดอัตโนมัติ → จดลง Log

5. ส่งเหตุการณ์ plugins:loaded
```

ผลที่ตามมาและควรจำ:

- **โค้ดถูกรันครั้งเดียวต่อ "รุ่นของไฟล์"** — กดโหลดใหม่โดยไฟล์ไม่เปลี่ยน = ไม่รันซ้ำ (กันของซ้อนสองชุด)
- **แก้ `plugin.json` อย่างเดียวก็นับว่าเปลี่ยน** → ปลั๊กอินถูกถอดแล้วรันใหม่
- **ลำดับการรัน**: ตามลำดับที่ระบบไฟล์คืนรายชื่อโฟลเดอร์ (โดยทั่วไปเรียงตามชื่อ) — **อย่าพึ่งลำดับ** ปลั๊กอินต้องทำงานได้ไม่ว่าตัวอื่นจะโหลดก่อนหรือหลัง (สื่อสารข้ามปลั๊กอินด้วยเหตุการณ์ — [4.2](04-hooks-lifecycle.md#42-เหตุการณ์ของปลั๊กอินเอง))
- **เปลี่ยนผลงาน**: ปลั๊กอินของผู้ใช้ที่ไฟล์ไม่เปลี่ยนทำงานต่อโดยไม่ถูกรันซ้ำ — ตัวแปรของปลั๊กอินจึง **ค้างข้ามผลงาน** ฟัง `project:open` เพื่อโหลดสภาพของผลงานใหม่ · ปลั๊กอินของผลงานเดิมถูกถอด ของผลงานใหม่ถูกโหลด
- **สถานะ "ปิดไว้" จำต่อผลงาน** — ปลั๊กอินตัวเดียวกันอาจเปิดในผลงานหนึ่งและปิดในอีกผลงาน

## 2.5 สภาพแวดล้อมที่โค้ดรัน

```js
new Function('k2', code)(k2)
```

| เรื่อง | ความจริง |
|---|---|
| ที่รัน | หน้าต่างหลักของโปรแกรม (Chromium ของ Electron 43) — เธรดเดียวกับ UI |
| ภาษา | JavaScript รุ่นใหม่ใช้ได้เต็มที่ (ES2023+ · `async/await` · optional chaining · `Intl.Segmenter` …) |
| โมดูล | **ไม่มี** `import` / `export` / `require` — ไฟล์เดียวเป็นสคริปต์ |
| `await` ระดับบนสุด | ไม่ได้ — ครอบด้วย `(async () => { … })();` |
| ขอบเขตตัวแปร | อยู่ในฟังก์ชันของปลั๊กอินเอง — `const`/`let`/`function` ระดับบนไม่ชนกับปลั๊กอินอื่น |
| โหมดเข้มงวด | ไม่ได้เปิดให้ — ใส่ `'use strict';` บรรทัดแรกได้ (แนะนำ) |
| DOM / Web API | ใช้ได้ทั้งหมด: `document` · `fetch` (ติด CORS — ใช้ `k2.fetch`) · `localStorage` · `IndexedDB` · `Canvas` · `WebAudio` · `Intl` |
| Node.js | **ไม่มี** `fs` · `path` · `process` · `Buffer` · `require` |
| `window.alert/prompt/confirm` | ใช้ไม่ได้ — ใช้ `k2.alertBox` · `k2.ask` · `k2.confirmBox` |
| Web Worker | สร้างได้จาก Blob URL ถ้างานหนักจริง — อย่าลืม `terminate()` ใน `onUnload` |
| ข้อผิดพลาดตอนรันระดับบน | ปลั๊กอินถูกปิดอัตโนมัติ |
| ข้อผิดพลาดใน callback (คำสั่ง · คีย์ลัด · ตัวรับเหตุการณ์ · `render`) | ถูกจับและจดลง Log — ไม่ทำให้ปลั๊กอินถูกปิด |
| งานหนักแบบซิงก์ | **ทำให้ทั้งโปรแกรมค้าง** — แบ่งงานด้วย `await` เป็นช่วง ๆ |

### `this` และตัวแปรระดับบน

```js
'use strict';
const VERSION = '1.2.0';          // ของปลั๊กอินนี้เท่านั้น
function helper() { /* … */ }     // เช่นกัน

window.myGlobal = 1;              // ✘ อย่าทำ — ชนกับโปรแกรม/ปลั๊กอินอื่น และค้างหลังถอน
```

ถ้าจำเป็นต้องแขวนอะไรบน `window` (เช่น ให้คอนโซลเรียกได้) ใช้ชื่อที่มีคำนำหน้าของปลั๊กอิน และ `delete` ใน `onUnload`

## 2.6 สถานะของปลั๊กอิน

| สถานะ (ป้ายบนการ์ด) | รหัส | เกิดเมื่อ | โค้ดถูกรันไหม |
|---|---|---|---|
| **รออนุญาต** | `untrusted` | อยู่ในโฟลเดอร์ผลงาน และชุดไฟล์ยังไม่ได้รับอนุญาต | ไม่ |
| **มีปัญหา** | `err` | `plugin.json` เสีย · อ่านไฟล์ entry ไม่ได้ · โค้ดโยน error ตอนรัน | รันแล้วพัง (ของที่ลงทะเบียนไปแล้วถูกถอด) |
| **รุ่นไม่พอ** | `old` | `minAppVersion` สูงกว่ารุ่นโปรแกรม | ไม่ |
| **ทำงานอยู่** | `ok` | โหลดสำเร็จ | ใช่ |
| **ปิดอยู่** | `off` | ผู้ใช้กดปิด — หรือเคยพังแล้วถูกปิดอัตโนมัติในรอบก่อน | ไม่ |

แผงเรียงการ์ดตาม: รออนุญาต → มีปัญหา → รุ่นไม่พอ → ทำงานอยู่ → ปิดอยู่ (ในกลุ่มเดียวกันเรียงตามชื่อ)

**ปลั๊กอินที่พังถูกปิดอัตโนมัติ** — เพื่อไม่ให้ปลั๊กอินตัวเดียวทำให้โปรแกรมเปิดไม่ขึ้นทุกครั้ง หลังแก้ไฟล์ผู้ใช้ต้องกด **เปิดใช้** บนการ์ด (กดโหลดใหม่อย่างเดียวจะเห็นเป็น "ปิดอยู่")
