# 4. ตะขอ (Hooks) และวงจรชีวิต

**ภาษา:** ไทย · [English](../en/04-hooks-lifecycle.md)

[← 3. SDK: ตัวแปร `k2`](03-sdk-reference.md) · [ภาพรวม](README.md) · ถัดไป: [5. หน้าตาและการใช้งาน →](05-ui-guidelines.md)

---

"ตะขอ" ของ Killian 2 มีสามชนิด:

| ชนิด | ใช้ทำอะไร | API |
|---|---|---|
| **เหตุการณ์ของโปรแกรม** | ทำงานเมื่อบางอย่างเกิดขึ้น (เปิดผลงาน · สลับแท็บ · บันทึก) | `k2.on(ชื่อ, fn)` |
| **ตะขอวงจรชีวิต** | เก็บกวาดเมื่อปลั๊กอินถูกถอด | `k2.onUnload(fn)` |
| **ตะขอนอกปลั๊กอิน** | ขั้น "JavaScript เอง" ของเวิร์กโฟลว์ส่งออก | [4.5](#45-ตะขออื่นนอกปลั๊กอิน) |

ตะขอทุกตัวเป็นแบบ **"แจ้งให้ทราบ"** — ปลั๊กอินรับรู้ได้ แต่ **ขวางหรือยกเลิกการกระทำของโปรแกรมไม่ได้** (ไม่มี before-save · ไม่มีการคืนค่าเพื่อเปลี่ยนผล)

## 4.1 เหตุการณ์ของโปรแกรม

| เหตุการณ์ | เกิดเมื่อ | ข้อมูล (payload) |
|---|---|---|
| `project:open` | เปิดผลงาน **และโหลดปลั๊กอินของผลงานนั้นเสร็จแล้ว** | `{ root, title }` |
| `project:close` | กำลังจะปิดผลงาน (ยังอ่านไฟล์ได้) | `{ root }` |
| `tab:activate` | แท็บที่เลือกอยู่เปลี่ยนเป็นแท็บอื่น | `{ file, title, kind }` |
| `tab:save` | บันทึกเอกสารลงดิสก์สำเร็จ | `{ file, title, chars }` |
| `plugins:loaded` | ตัวโหลดปลั๊กอินทำงานเสร็จหนึ่งรอบ | `{ loaded: string[] }` |

ทุก payload เป็นข้อมูลล้วน (สตริง/ตัวเลข/อาร์เรย์) — โปรแกรมไม่ส่งวัตถุภายในให้ปลั๊กอิน

### `project:open`

```js
k2.on('project:open', (e) => {
  // e.root  = ทางเต็มของโฟลเดอร์ผลงาน (ของเครื่องนี้ — อย่าจดลงไฟล์)
  // e.title = ชื่อผลงาน
  state = k2.getSettings('state', null);      // โหลดสภาพของผลงานใหม่
  redraw();
});
```

- ถูกส่ง **หลัง** ปลั๊กอินของรอบนั้นรันแล้ว → ปลั๊กอินที่เพิ่งถูกโหลดเพราะการเปิดผลงานนี้ **ก็ได้รับ** เหตุการณ์
- ปลั๊กอินของผู้ใช้ที่ทำงานอยู่ก่อนแล้ว **ไม่ถูกรันซ้ำ** เมื่อเปลี่ยนผลงาน — เหตุการณ์นี้คือสัญญาณเดียวว่า "ผลงานเปลี่ยนแล้ว" ต้องล้าง/โหลดข้อมูลที่ผูกกับผลงานเก่าเอง (ค่าจาก `getSettings` · แคชของไฟล์ · สิ่งที่แสดงในแผง)

### `project:close`

```js
k2.on('project:close', (e) => { cache.clear(); });
```

- ส่งก่อนโปรแกรมเก็บกวาดผลงาน — ยังเรียก `k2.readFile` ได้ **แต่โปรแกรมไม่รอ Promise** งานที่ต้องเสร็จให้ทำแบบซิงก์ (เช่น `k2.setSettings`)
- อย่าเขียนไฟล์ในจังหวะนี้ถ้าเลี่ยงได้ — บันทึกสภาพเป็นระยะระหว่างทำงานดีกว่า

### `tab:activate`

```js
k2.on('tab:activate', (e) => {
  // e.file  = ทางเต็มของไฟล์ในแท็บ
  // e.title = ชื่อบนแท็บ
  // e.kind  = 'prose' | 'screenplay' | 'wiki' | 'other'
  panelTitle = e.title;
  redraw();
});
```

| `kind` | แท็บ | `getMarkdown()` · `getEditorView()` |
|---|---|---|
| `'prose'` | ฉาก/Memo โหมดนิยาย | ใช้ได้ |
| `'screenplay'` | ฉากโหมดบทภาพยนตร์ | ใช้ได้ (ข้อความมีรหัสนำหน้าบรรทัด) |
| `'wiki'` | หน้าเอนทิตี้ Wiki | `''` / `null` |
| `'other'` | ไฟล์ชนิดอื่น | `''` / `null` |

- ส่งเฉพาะเมื่อแท็บ **เปลี่ยนจริง** (คลิกแท็บเดิมซ้ำไม่ส่ง) — รวมตอนเปิดแท็บแรก
- **ไม่มีเหตุการณ์ "ปิดแท็บสุดท้าย"** — ถ้าต้องรู้ว่าไม่มีเอกสารเปิด ตรวจ `k2.getEditorView() === null` ตอนจะใช้
- ผู้ใช้สลับแท็บถี่ได้ — หน่วงงานหนักไว้ (debounce) อย่าอ่านไฟล์ทุกครั้งที่สลับ

### `tab:save`

```js
k2.on('tab:save', (e) => {
  // e.file  = ทางเต็มของไฟล์ที่บันทึก
  // e.title = ชื่อเอกสาร
  // e.chars = จำนวนอักขระของเนื้อเรื่องที่บันทึก
  total += e.chars;
});
```

- ส่งหลังเขียนลงดิสก์ **สำเร็จ** — ทั้งการบันทึกเอง (`Ctrl+S`) · **บันทึกทั้งหมด** · และ **บันทึกอัตโนมัติ**
- ใช้กับเอกสารที่มีเนื้อ `.md` (ฉาก · Memo) — การบันทึกหน้า Wiki · กระดาน · ผัง ไม่ส่งเหตุการณ์นี้
- บันทึกทั้งหมดส่งเหตุการณ์ **ทีละไฟล์** ติด ๆ กัน — ถ้างานของคุณแพง ให้รวบ (debounce) แล้วทำครั้งเดียว
- ⚠ **`k2.setStatus` ใน handler นี้จะถูกทับ** — โปรแกรมเขียน "บันทึกแล้ว: <ชื่อ>" ลงแถบสถานะต่อจากเหตุการณ์ทันที แสดงผลในแผงของคุณแทน หรือหน่วง:

  ```js
  k2.on('tab:save', () => setTimeout(() => k2.setStatus('…'), 0));
  ```
- `k2.getMarkdown()` ใน handler ได้เนื้อของ **แท็บที่เลือกอยู่** ซึ่งอาจไม่ใช่ไฟล์ที่เพิ่งบันทึก (กรณีบันทึกทั้งหมด/อัตโนมัติ) — ต้องการเนื้อของไฟล์ที่บันทึกจริงให้ `k2.readFile` ด้วยทางสัมพัทธ์ของ `e.file`

### `plugins:loaded`

```js
k2.on('plugins:loaded', (e) => {
  hasFriend = e.loaded.includes('other-plugin');     // ชื่อโฟลเดอร์ของปลั๊กอินที่ทำงานอยู่
});
```

- ส่งท้ายทุกรอบของตัวโหลด (เปิดผลงาน · ผู้ใช้กดโหลดใหม่/เปิด/ปิด/ติดตั้ง/ถอน)
- ปลั๊กอินที่เพิ่งถูกรันในรอบนั้นได้รับด้วย — ใช้เป็นจุด "ทุกตัวพร้อมแล้ว" สำหรับงานที่ต้องคุยกับปลั๊กอินอื่น

### เปลี่ยนทางเต็มเป็นทางสัมพัทธ์

`e.file` และ `e.root` เป็นทางเต็มของเครื่อง — ก่อนส่งให้ `k2.readFile` หรือเก็บลงค่าตั้ง:

```js
function relPath(full) {
  const root = String(k2.projectRoot() || '').replace(/\\/g, '/').replace(/\/+$/, '');
  const p = String(full || '').replace(/\\/g, '/');
  return root && p.startsWith(root + '/') ? p.slice(root.length + 1) : null;   // null = อยู่นอกผลงาน
}
```

## 4.2 เหตุการณ์ของปลั๊กอินเอง

ปลั๊กอินคุยกันผ่านบัสเดียวกัน:

```js
// ปลั๊กอิน A — ประกาศ
k2.emit('focus-timer:done', { minutes: 25 });

// ปลั๊กอิน B — ฟัง
k2.on('focus-timer:done', (e) => k2.log('ครบ ' + e.minutes + ' นาที'));
```

| กติกา | เหตุผล |
|---|---|
| ชื่อ = `<ชื่อโฟลเดอร์ปลั๊กอิน>:<เรื่อง>` | ไม่ชนกับปลั๊กอินอื่น และรู้ว่าใครส่ง |
| **ห้ามส่งชื่อเหตุการณ์ของโปรแกรม** (`project:*` · `tab:*` · `plugins:*`) | ตัวรับจะเข้าใจผิดว่าเกิดขึ้นจริง |
| payload เป็นข้อมูลล้วน | ตัวรับอาจอยู่คนละรุ่น/คนละผู้เขียน — ส่งวัตถุที่มีพฤติกรรม = ผูกกันแน่นเกินไป |
| เขียนรูปของ payload ไว้ใน README | เป็น API สาธารณะของปลั๊กอินคุณ — เปลี่ยนแล้วถือเป็น breaking change |
| ตัวรับต้องทนได้เมื่อไม่มีใครส่ง และตัวส่งต้องทนได้เมื่อไม่มีใครรับ | ลำดับการโหลดไม่แน่นอน · ผู้ใช้อาจปิดอีกตัว |

`k2.emit` คืนจำนวนตัวรับ — ใช้ตรวจว่ามีใครฟังอยู่ไหมได้

## 4.3 วงจรชีวิต และ `hotReload`

### ช่วงชีวิตของปลั๊กอินหนึ่งตัว

```
[ไฟล์บนดิสก์]
     │  ผู้ใช้เปิดผลงาน / กดโหลดใหม่ / เปิดใช้ / ติดตั้ง
     ▼
 ┌─ รัน ──────────────────────────────────────────────┐
 │ new Function('k2', code)(k2)                        │
 │   • ลงทะเบียน: คำสั่ง · คีย์ลัด · แผง · ตัวรับเหตุการณ์  │ ← โปรแกรมจดไว้ในระเบียนของปลั๊กอิน
 │   • k2.onUnload(fn)                                 │
 │   • ของที่สร้างเอง: timer · listener · element · style │ ← โปรแกรมมองไม่เห็น
 └────────────────────────────────────────────────────┘
     │
     ▼
 [ทำงานอยู่] ── เหตุการณ์ · คำสั่ง · คีย์ลัด · render ──┐
     │                                              └─ วนอยู่ตรงนี้
     │  ผู้ใช้ปิด / ถอน / แก้ไฟล์แล้วโหลดใหม่ / ติดตั้งทับ / เปลี่ยนผลงาน (ปลั๊กอินของผลงาน)
     ▼
 ┌─ ถอด ──────────────────────────────────────────────┐
 │ 1. เรียก onUnload(why) ทุกตัว (ย้อนลำดับ)             │
 │ 2. ถอนตัวรับเหตุการณ์                                │
 │ 3. ถอนคีย์ลัด                                        │
 │ 4. ปิดและถอนทะเบียนแผง                               │
 │ 5. ถอนคำสั่ง                                         │
 │ 6. ไม่ได้ประกาศ hotReload (หรือ onUnload โยน error)   │
 │    → จดชื่อลงรายการ "ต้องเริ่มโปรแกรมใหม่"             │
 └────────────────────────────────────────────────────┘
     │  (กรณีแก้ไฟล์: ตัวใหม่ถูกรันต่อทันที)
     ▼
 [จบ]
```

### สิ่งที่โปรแกรมถอนให้เอง กับสิ่งที่คุณต้องถอนเอง

| ถอนให้เอง (ลงทะเบียนผ่าน `k2`) | ต้องถอนเองใน `onUnload` |
|---|---|
| `registerCommand` / `addMenuItem` | `setInterval` · `setTimeout` ที่ยังไม่ยิง · `requestAnimationFrame` |
| `registerShortcut` | `addEventListener` บน `window` / `document` / element ของโปรแกรม |
| `registerPanel` (แผงถูกปิดและถอน) | element ที่ `append` เข้า `<body>` หรือที่อื่นนอกแผงของตัวเอง |
| `on` (ตัวรับเหตุการณ์) | `<style>` / `<link>` ที่ฉีดเข้า `<head>` |
| | `MutationObserver` · `ResizeObserver` · `IntersectionObserver` |
| | `Worker` · `WebSocket` · `AudioContext` · `BroadcastChannel` |
| | ตัวแปรที่แขวนบน `window` |
| | คำขอ `k2.fetch` ที่ยังค้าง (ทำธง "ถูกถอดแล้ว" ไว้ให้ callback เช็ค) |

element และตัวฟังที่อยู่ **ภายใน `host` ของแผงตัวเอง** ไม่ต้องถอน — หายไปพร้อมแผง

### `hotReload` — คำมั่นของผู้เขียน

`"hotReload": true` ใน `plugin.json` = **"ฉันรับรองว่า `onUnload` ของฉันเก็บกวาดทุกอย่างในคอลัมน์ขวาครบ"**

| ปลั๊กอิน | เมื่อถูกปิด / ถอน / แก้ไฟล์ / ติดตั้งทับ |
|---|---|
| ประกาศ `"hotReload": true` | ออกทันที ไม่มีคำเตือน |
| ไม่ประกาศ (ค่าเริ่มต้น) | แผงปลั๊กอินขึ้นแถบ **"ต้องเริ่มโปรแกรมใหม่เพื่อถอดปลั๊กอินออกให้หมด"** + ข้อความลอยพร้อมปุ่มเริ่มใหม่ — ค้างจนกว่าผู้ใช้จะเริ่มโปรแกรมใหม่จริง |

- **ติดตั้ง/เปิดใช้ครั้งแรกไม่ต้องเริ่มโปรแกรมใหม่** ทุกกรณี
- `onUnload` **โยน error** → โปรแกรมถือว่าเก็บไม่ครบ → แจ้งให้เริ่มใหม่แม้ประกาศ `hotReload`
- ปลั๊กอิน **พังกลางการรันครั้งแรก** → ถูกถอดด้วย `why = 'error'` และเข้ากติกาเดียวกัน
- การ์ดของปลั๊กอินบอกผู้ใช้ล่วงหน้า: "ปิด/ถอนได้ทันที" หรือ "ปิด/ถอนแล้วต้องเริ่มโปรแกรมใหม่"

**ประกาศ `hotReload` แล้วเก็บไม่ครบ = บั๊กที่ผู้ใช้หาสาเหตุไม่ได้**: ตัวจับเวลาค้างยิงโค้ดของรุ่นเก่า · ตัวฟังซ้อนสองชุด · ของลอยค้างบนจอ — ถ้าไม่แน่ใจ **อย่าประกาศ** คำเตือนให้เริ่มใหม่ดีกว่าพฤติกรรมผี

### แบบแผนที่แนะนำ: ลงคู่กันทุกครั้ง

```js
'use strict';

// ตัวช่วย: สร้างของ + ลงตัวถอนในบรรทัดเดียว
const cleanups = [];
const track = (undo) => { cleanups.push(undo); };
k2.onUnload(() => { for (const fn of cleanups.splice(0).reverse()) { try { fn(); } catch (e) { k2.log('cleanup: ' + e.message); } } });

function listen(target, type, fn, opts) {
  target.addEventListener(type, fn, opts);
  track(() => target.removeEventListener(type, fn, opts));
}
function every(ms, fn) {
  const id = setInterval(fn, ms);
  track(() => clearInterval(id));
  return id;
}
function mount(el, parent = document.body) {
  parent.append(el);
  track(() => el.remove());
  return el;
}

// ใช้งาน
listen(window, 'keydown', (e) => { if (e.code === 'F2' && e.ctrlKey && e.shiftKey) doIt(); });
every(60000, tick);
mount(Object.assign(document.createElement('style'), { textContent: '.myplug-x{…}' }), document.head);
```

ตัวอย่างนี้จับ error ของตัวถอนแต่ละตัวไว้เอง จึงไม่ทำให้ `onUnload` โยน — ตัวถอนตัวหนึ่งพังแล้วตัวที่เหลือยังถูกเรียก

### `'reload'` กับ `'remove'`

```js
k2.onUnload((why) => {
  if (why === 'reload') sessionStorage.setItem(NS + ':carry', JSON.stringify(state));   // ส่งต่อให้รุ่นใหม่
  else sessionStorage.removeItem(NS + ':carry');
});

// ตอนเริ่ม (รุ่นใหม่)
const carried = JSON.parse(sessionStorage.getItem(NS + ':carry') || 'null');
```

`'reload'` = ไฟล์เปลี่ยนและตัวใหม่กำลังจะรันต่อทันที — ระหว่างพัฒนาคุณจะเจอจังหวะนี้ทุกครั้งที่กดโหลดใหม่

## 4.4 ตารางสรุป: เกิดอะไรเมื่อ…

| ผู้ใช้ทำ | ปลั๊กอินของผู้ใช้ | ปลั๊กอินของผลงาน |
|---|---|---|
| เปิดผลงาน (ครั้งแรกของรอบโปรแกรม) | รัน → `plugins:loaded` → `project:open` | ได้รับอนุญาตแล้ว: รัน · ยังไม่อนุญาต: ไม่รัน |
| กด **โหลดใหม่** ไฟล์ไม่เปลี่ยน | ไม่มีอะไรเกิด (ไม่รันซ้ำ) → `plugins:loaded` | เหมือนกัน |
| กด **โหลดใหม่** ไฟล์เปลี่ยน | `onUnload('reload')` → ถอน → รันใหม่ | เหมือนกัน + ต้องอนุญาตใหม่ก่อน (ลายนิ้วมือเปลี่ยน) |
| กด **ปิด** | `onUnload('remove')` → ถอน | เหมือนกัน |
| กด **เปิดใช้** | รัน | รัน |
| **ถอนออก** / ลบโฟลเดอร์แล้วโหลดใหม่ | `onUnload('remove')` → ถอน → โฟลเดอร์ถูกลบ | เหมือนกัน |
| **ติดตั้งทับ** | `onUnload('reload')` → ถอน → รันรุ่นใหม่ | — (ติดตั้งจากลิงก์ลงโฟลเดอร์ผู้ใช้เสมอ) |
| เปลี่ยนไปผลงานอื่น | **ทำงานต่อ ไม่ถูกรันซ้ำ** → `project:close` → … → `project:open` | ของผลงานเก่า: `onUnload('remove')` · ของผลงานใหม่: รัน (ถ้าอนุญาตแล้ว) |
| ปิดโปรแกรม | หน้าต่างถูกทำลาย — **`onUnload` ไม่ถูกเรียก** | เหมือนกัน |

> **อย่าพึ่ง `onUnload` เพื่อบันทึกข้อมูล** — ปิดโปรแกรมแล้วมันไม่ถูกเรียก บันทึกสภาพทันทีที่เปลี่ยน (`k2.setSettings`) หรือเป็นระยะ

## 4.5 ตะขออื่นนอกปลั๊กอิน

### ขั้น "สคริปต์ JavaScript เอง" ของเวิร์กโฟลว์ส่งออก

ผู้ใช้ (ไม่ต้องเป็นปลั๊กอิน) ใส่โค้ดลงในขั้นสุดท้ายของเวิร์กโฟลว์ส่งออกได้: **ส่งออก → ปรับขั้นตอนเวิร์กโฟลว์ส่งออก…** → เปิดขั้น **สคริปต์ JavaScript เอง**

```js
// ตัวแปรที่ได้: text (ข้อความทั้งหมดหลังขั้นก่อนหน้า) · model (โครงเอกสาร: ชื่อเรื่อง บท ฉาก)
// ต้อง return สตริง
return text
  .replace(/\.{3}/g, '…')                       // สามจุด → จุดไข่ปลา
  .replace(/ +\n/g, '\n');                      // ตัดวรรคท้ายบรรทัด
```

| เรื่อง | |
|---|---|
| รันเมื่อ | ทุกครั้งที่ส่งออกด้วยเวิร์กโฟลว์นั้น (รวมตอนสร้างตัวอย่างในศูนย์ส่งออก) |
| ลายเซ็น | `(text: string, model: object) => string` — เป็นเนื้อของฟังก์ชัน (ใช้ `return`) |
| คืนค่าที่ไม่ใช่สตริง | ขั้นนี้ถูกข้าม + คำเตือน |
| โยน error | ขั้นนี้ถูกข้าม + คำเตือนพร้อมข้อความ error — การส่งออกไม่ล้ม |
| ทำงานแบบ | ซิงก์ — ไม่มี `await` |
| อยู่ช่วงไหน | "ข้อความสุดท้าย" — หลังประกอบบท/ฉากและหลังแปลงเป็น HTML (ถ้าเปิด) ดังนั้น `text` อาจเป็นมาร์กดาวน์หรือ HTML ขึ้นกับเวิร์กโฟลว์ |
| เก็บที่ | ในเวิร์กโฟลว์ ซึ่งอยู่ใน `project.khn.json` ของผลงาน |

เหมาะกับการแปลงข้อความเฉพาะกิจตอนส่งออก (แทนเครื่องหมาย · ใส่หัวท้าย · กรองบรรทัด) โดยไม่ต้องทำปลั๊กอิน — โค้ดรันในหน้าต่างของโปรแกรมด้วยสิทธิ์เดียวกับปลั๊กอิน จึง **อย่าวางโค้ดจากคนที่ไม่รู้จัก**

จุดต่อขยายแบบไฟล์ข้อมูล (ภาษา · พจนานุกรม · ทักษะ AI · เทมเพลต) อยู่ที่ [บทที่ 10](10-other-extension-points.md)

## 4.6 แบบแผนที่ใช้บ่อย

### หน่วงงาน (debounce)

```js
function debounce(fn, ms) {
  let id = 0;
  const run = (...a) => { clearTimeout(id); id = setTimeout(() => fn(...a), ms); };
  k2.onUnload(() => clearTimeout(id));          // timeout ที่ยังไม่ยิงก็ต้องเก็บ
  return run;
}
const refresh = debounce(async () => { /* งานแพง */ }, 400);
k2.on('tab:save', refresh);
k2.on('tab:activate', refresh);
```

### ฟังครั้งเดียว

```js
const off = k2.on('project:open', (e) => { off(); init(e); });
```

### งานที่ต้องรู้ว่ายังอยู่ไหมหลัง `await`

```js
let alive = true;
k2.onUnload(() => { alive = false; });

k2.on('tab:save', async (e) => {
  const rootAtStart = k2.projectRoot();
  const r = await k2.fetch(URL, { /* … */ });
  if (!alive) return;                            // ปลั๊กอินถูกถอดระหว่างรอ — อย่าแตะอะไรต่อ
  if (k2.projectRoot() !== rootAtStart) return;  // ผู้ใช้เปลี่ยนผลงานระหว่างรอ
  draw(r);
});
```

### ตรวจสภาพเป็นระยะ (เมื่อไม่มีเหตุการณ์ให้ฟัง)

ไม่มีเหตุการณ์ "ข้อความเปลี่ยน" หรือ "ช่วงที่เลือกเปลี่ยน" — ถ้าจำเป็นจริง ๆ:

```js
let lastLen = -1;
const id = setInterval(() => {
  if (document.hidden) return;                   // หน้าต่างไม่ได้อยู่หน้า — ไม่ต้องทำ
  const v = k2.getEditorView();
  const len = v ? v.state.doc.content.size : -1; // ถูกกว่า getMarkdown() มาก
  if (len === lastLen) return;
  lastLen = len;
  onDocChanged();
}, 1000);
k2.onUnload(() => clearInterval(id));
```

- ช่วงเวลา ≥ 1 วินาที · ตรวจด้วยของถูก (ขนาดเอกสาร) ก่อนทำของแพง (`getMarkdown`)
- **อย่าใช้ `MutationObserver` กับ DOM ของตัวแก้ไขหรือแถบของโปรแกรม** — มันยิงทุกการกดแป้น ทำให้ทั้งโปรแกรมช้า

## 4.7 สิ่งที่ตะขอทำไม่ได้ (ในรุ่นนี้)

| อยากทำ | สถานะ |
|---|---|
| ขวาง/ยกเลิกการบันทึก · การลบ · การส่งออก | ไม่ได้ — ไม่มีตะขอแบบ "ก่อน…" |
| แก้เนื้อหาก่อนถูกเขียนลงไฟล์ | ไม่ได้ |
| รู้ทุกครั้งที่ผู้ใช้พิมพ์/เลือกข้อความ | ไม่มีเหตุการณ์ (ดู 4.6) |
| รู้เมื่อสร้าง/ลบ/ย้าย/เปลี่ยนชื่อฉาก บท เล่ม เอนทิตี้ | ไม่มีเหตุการณ์ — ตรวจจากไฟล์ทะเบียนเมื่อจะใช้ |
| รู้เมื่อธีม/ภาษา/ค่าตั้งเปลี่ยน | ไม่มีเหตุการณ์ — ใช้ตัวแปร CSS ของธีม (เปลี่ยนตามเอง) |
| รู้เมื่อโปรแกรมกำลังจะปิด | ไม่มี |
| ลำดับความสำคัญของตัวรับ | ไม่มี — เรียกตามลำดับที่ลง |

ต้องการตะขอใหม่: เสนอผ่านรายงานในโปรแกรม (ช่วยเหลือ → รายงานบั๊ก) หรือ pull request — ผู้ดูแลเพิ่มด้วยการเรียก `pluginBus.emit('<เรื่อง>:<กริยา>', {ข้อมูลล้วน})` ที่จุดเกิดเหตุ พร้อมแถวในตารางของเอกสารนี้
