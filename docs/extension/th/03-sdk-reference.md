"SDK" ของ Killian 2 คือ object ชื่อ **`k2`** ที่โปรแกรมสร้างให้ปลั๊กอินแต่ละตัว (คนละก้อน ผูกกับชื่อของปลั๊กอินนั้น) ไม่มีแพ็กเกจให้ติดตั้ง — ชนิดข้อมูลสำหรับตัวแก้โค้ดอยู่ใน [`k2.d.ts`](../k2.d.ts)

เอกสารนี้ตรงกับ `pluginApi()` ใน `src/app.js` ของรุ่น **alpha.169**

## 3.1 ข้อมูล

### `k2.pluginName` : `string`

ชื่อโฟลเดอร์ของปลั๊กอินนี้ — ใช้เป็นคำนำหน้าของทุกอย่างที่ต้องไม่ชนกับปลั๊กอินอื่น

```js
const NS = 'k2-plugin-' + k2.pluginName;             // คำนำหน้าคลาส CSS / คีย์ localStorage / ชื่อเหตุการณ์
```

### `k2.appVersion` : `string`

รุ่นของโปรแกรม เช่น `"2.0.0-alpha.169"`

```js
const alpha = Number((k2.appVersion.match(/alpha\.(\d+)/) || [])[1] || Infinity);
```

### `k2.projectRoot()` → `string | null`

ทางเต็มของโฟลเดอร์ผลงานที่เปิดอยู่ · `null` = ยังไม่มีผลงานเปิด

- เป็น **ทางของเครื่องผู้ใช้** (`C:\Users\…` / `/Users/…`) — **ห้ามจดลงไฟล์ของผลงาน** และอย่าส่งออกนอกเครื่อง
- เรียกทุกครั้งที่ต้องใช้ อย่าเก็บค่าไว้ — ผู้ใช้เปลี่ยนผลงานได้โดยปลั๊กอินไม่ถูกรันใหม่

## 3.2 คำสั่งและคีย์ลัด

### `k2.registerCommand(label, fn)` → `true` 🔄

เพิ่มคำสั่งของปลั๊กอิน

| พารามิเตอร์ | ชนิด | |
|---|---|---|
| `label` | `string` | ชื่อที่ผู้ใช้เห็น — สั้น ขึ้นต้นด้วยกริยา ("นับคำฉากนี้") |
| `fn` | `() => void \| Promise<void>` | ถูกเรียกเมื่อผู้ใช้กด · โยน error ได้ (ถูกจับและจดลง Log) |

คำสั่งโผล่ 2 ที่:

1. **การ์ดของปลั๊กอิน** ในแผงปลั๊กอิน ("คำสั่งที่เพิ่มเข้ามา")
2. ปุ่ม **คำสั่งจากปลั๊กอิน** บนแถบเครื่องมือ (ปุ่มโผล่เมื่อมีปลั๊กอินอย่างน้อยหนึ่งตัวลงทะเบียนคำสั่ง · แถบแคบ = อยู่ในปุ่ม »)

```js
k2.registerCommand('นับคำฉากนี้', () => {
  k2.setStatus(k2.getMarkdown().length + ' ตัวอักษร');
});

k2.registerCommand('ส่งออกรายงาน…', async () => {      // async ได้
  if (!(await k2.confirmBox('สร้างรายงาน?', 'สร้าง'))) return;
  // …
});
```

- ลงทะเบียนเพิ่มทีหลังได้ (เช่น หลัง `await`) — รายการอ่านสดทุกครั้ง
- ไม่มี id ของคำสั่ง และ **ไม่มีทางถอนทีละคำสั่ง** — คำสั่งหายเมื่อปลั๊กอินถูกถอด
- ปลั๊กอินเพิ่มรายการบน **แถบเมนูของระบบไม่ได้**

### `k2.addMenuItem(label, fn)` → `true` 🔄

ชื่อเดิมของ `registerCommand` — ทำงานเหมือนกันทุกประการ คงไว้เพื่อปลั๊กอินเก่า ใช้ `registerCommand` ในโค้ดใหม่

### `k2.registerShortcut(id, code, ctrl, shift, fn)` → `string` 🔄

จองคีย์ลัด คืนชื่อช่อง `plugin:<ชื่อปลั๊กอิน>:<id>`

| พารามิเตอร์ | ชนิด | |
|---|---|---|
| `id` | `string` | ชื่อของคีย์ลัดในปลั๊กอินนี้ — ลงทะเบียน id เดิมซ้ำ = แทนของเก่า |
| `code` | `string` | **`KeyboardEvent.code`** = ตำแหน่งปุ่มกายภาพ: `'KeyK'` · `'F8'` · `'Digit1'` · `'BracketRight'` · `'Slash'` — ทำงานทุกภาษาแป้นพิมพ์ |
| `ctrl` | `boolean` | **ต้องเป็น `true`** (ค่าเริ่มต้น) — `Ctrl` บน Windows/Linux · `⌘` บน macOS |
| `shift` | `boolean` | `true` = ต้องกด `Shift` ด้วย |
| `fn` | `() => void \| Promise<void>` | ถูกเรียกเมื่อกดคีย์ |

```js
k2.registerShortcut('count', 'F8', true, true, () => report());      // Ctrl+Shift+F8
k2.registerShortcut('stamp', 'KeyJ', true, true, () => stamp());     // Ctrl+Shift+J ← ชน! ดูข้างล่าง
```

**ข้อจำกัดของรุ่นนี้ — อ่านให้ครบ**

- **คีย์ลัดของปลั๊กอินต้องมี `Ctrl`/`⌘` เสมอ** — ตัวดักคีย์ลัดของโปรแกรมทำงานเฉพาะตอนกด Ctrl/⌘ ค้าง ส่ง `ctrl = false` แล้วคีย์ลัดนั้น **จะไม่ทำงานเลย**
- **ใช้ `Alt` ร่วมไม่ได้** — คีย์ลัดของปลั๊กอินตรงเฉพาะตอน *ไม่ได้* กด Alt (ชุดที่ใช้ได้: `Ctrl+ปุ่ม` · `Ctrl+Shift+ปุ่ม`)
- **ชนกับคีย์ลัดของโปรแกรม = ของโปรแกรมชนะ** และคีย์ของปลั๊กอินไม่ถูกเรียก — ไม่มีการเตือน
  ตรวจตารางที่ [ภาคผนวก B ของคู่มือผู้ใช้](../../manual/th/B-shortcuts.md) ก่อนเลือก · ผู้ใช้ตั้งคีย์ของโปรแกรมใหม่ได้ จึงควรมีคำสั่ง (`registerCommand`) คู่กับคีย์ลัดเสมอ
- ผู้ใช้ **ตั้งคีย์ลัดของปลั๊กอินใหม่ไม่ได้** (หน้า ตั้งค่า → ปุ่มลัด ไม่แสดงคีย์ของปลั๊กอิน) — ถ้าอยากให้เปลี่ยนได้ ทำค่าตั้งของปลั๊กอินเอง
- ในช่องกรอกข้อความทั่วไป คีย์ลัดยังทำงาน — อย่าใช้ชุดที่ผู้ใช้กดประจำตอนพิมพ์

**ชุดปุ่มที่มักว่าง** (รุ่น alpha.169 — ตรวจซ้ำกับรุ่นจริงเสมอ): `Ctrl+Shift+F1…F12` · `Ctrl+F1…F12`

## 3.3 ตัวแก้ไข

"ตัวแก้ไขที่เปิดอยู่" = แท็บที่ผู้ใช้เลือกอยู่ ถ้าเป็นฉากนิยาย บทภาพยนตร์ หรือ Memo — แท็บหน้า Wiki และแผงต่าง ๆ ไม่มีตัวแก้ไขแบบนี้

### `k2.getMarkdown()` → `string`

มาร์กดาวน์ของเอกสารในแท็บที่เปิดอยู่ (เนื้อเรื่องเท่านั้น ไม่รวมหัวไฟล์) · ไม่มีตัวแก้ไข = `''`

- ได้เนื้อหา **ล่าสุดในแท็บ** รวมที่ยังไม่บันทึก
- บทภาพยนตร์ได้ข้อความพร้อมรหัสนำหน้าบรรทัด (`### ` `@` `>> ` …) — ไวยากรณ์ที่ [ภาคผนวก D ของคู่มือผู้ใช้](../../manual/th/D-file-formats.md)
- ทำงานแบบซิงก์ — เอกสารยาวมากเรียกถี่ ๆ จะหน่วง อย่าเรียกทุกการกดแป้น

### `k2.insertText(text)` → `boolean`

แทรกข้อความล้วนที่ตำแหน่งเคอร์เซอร์ (แทนที่ช่วงที่เลือกอยู่) และทำเครื่องหมายว่าแท็บยังไม่บันทึก · คืน `false` ถ้าไม่มีตัวแก้ไข

- เป็น **หนึ่งขั้นของ undo** — ผู้ใช้ `Ctrl+Z` ย้อนได้
- แทรกเป็น *ข้อความ* ในบล็อกปัจจุบัน — `\n` ไม่ได้สร้างย่อหน้าใหม่ และเครื่องหมายมาร์กดาวน์ (`**…**`) ไม่ถูกแปลงเป็นรูปแบบ
- ต้องการแทรกหลายย่อหน้าหรือรูปแบบ: ใช้ `getEditorView()` สร้าง transaction เอง
- ฉากที่ **ล็อก** หรือกำลังดู "ฉบับเดิม" ของฉากมีปัญหา เป็นเอกสารอ่านอย่างเดียว — อย่าพยายามแก้ และบอกผู้ใช้แทน

### `k2.getEditorView()` → `EditorView | null`

`EditorView` ของ [ProseMirror](https://prosemirror.net/docs/ref/#view.EditorView) ของแท็บที่เปิดอยู่

```js
const view = k2.getEditorView();
if (view) {
  const { from, to, empty } = view.state.selection;
  const selected = view.state.doc.textBetween(from, to, '\n');     // ข้อความที่เลือก
  // แทนที่ช่วงที่เลือกด้วยตัวพิมพ์ใหญ่ (หนึ่งขั้นของ undo)
  if (!empty) view.dispatch(view.state.tr.insertText(selected.toUpperCase(), from, to));
  view.focus();
}
```

กติกา:

- **แก้เนื้อหาผ่าน `view.dispatch(tr)` เท่านั้น** — ห้ามแตะ DOM ใน `.ProseMirror` (ใส่คลาส/element/สไตล์): ตัวจัดหน้าวัดจาก DOM จริง จะเพี้ยนทั้งเอกสาร และของที่ใส่จะหายเมื่อ ProseMirror วาดใหม่
- transaction ที่เปลี่ยนเนื้อหาทำให้แท็บขึ้นสถานะ "ยังไม่บันทึก" เอง และเป็นหนึ่งขั้นของ undo — รวมการแก้หลายจุดไว้ใน transaction เดียวเพื่อให้ผู้ใช้ย้อนได้ในครั้งเดียว
- schema ของนิยายกับบทภาพยนตร์ **ต่างกัน** (บทไม่มีบางโหนด/มาร์ก) — ตรวจ `view.state.schema.nodes` ก่อนสร้างโหนด
- ชื่อโหนด/มาร์กใน schema เป็นของภายใน **เปลี่ยนได้ทุกรุ่น** — พึ่งเท่าที่จำเป็น และทดสอบกับทุกรุ่นที่ประกาศรองรับ
- อย่าเก็บ `view` ไว้ข้ามเวลา — ผู้ใช้สลับแท็บแล้ว view เปลี่ยน เรียก `getEditorView()` ใหม่ทุกครั้ง

## 3.4 แผง

### `k2.registerPanel(id, opts)` → `string | null` 🔄

ลงทะเบียนแผงของปลั๊กอิน คืน id จริงของแผง (`plugin-<ชื่อปลั๊กอิน>-<id>`) หรือ `null` ถ้าลงทะเบียนไม่สำเร็จ

| `opts` | ชนิด | ค่าเริ่มต้น | |
|---|---|---|---|
| `title` | `string` | `id` | ชื่อบนหัวแผง |
| `icon` | `string` | `'extension'` | ชื่อไอคอนของโปรแกรม (จากทะเบียน `icons/glyphs.csv` เช่น `'chart'` `'note'` `'timer'` `'book'` `'image'` `'chat'` `'map'`) |
| `defaultSide` | `'left' \| 'right' \| 'bottom'` | `'right'` | ฝั่งที่ผนึกเมื่อผู้ใช้ผนึกครั้งแรก |
| `closable` | `boolean` | `true` | ผู้ใช้ปิดแผงได้ |
| `floatable` | `boolean` | `true` | ผู้ใช้ทำให้ลอยได้ |
| `render` | `(host: HTMLElement) => void` | — | วาดเนื้อแผงลงใน `host` |

```js
let host = null;
function draw() {
  if (!host) return;
  const el = document.createElement('div');
  el.className = 'myplug-body';
  el.textContent = 'สวัสดี';
  host.replaceChildren(el);
}
k2.registerPanel('main', { title: 'แผงของฉัน', icon: 'chart', render: (h) => { host = h; draw(); } });
```

กติกาของ `render`:

- **ถูกเรียกซ้ำได้หลายครั้ง** (เปิดแผง · ย้าย · พับ/คลี่ · เปลี่ยนเวิร์กสเปซ) และ `host` อาจเป็น element ใหม่ทุกครั้ง → เขียนให้เรียกซ้ำแล้วได้ผลเดิม (`host.replaceChildren(…)`) และเก็บ `host` ล่าสุดไว้สำหรับวาดใหม่เอง
- สภาพของแผง (ข้อมูล · ตำแหน่งเลื่อน · ค่าที่ผู้ใช้กรอก) ต้องเก็บใน **ตัวแปรของปลั๊กอิน** ไม่ใช่ใน DOM
- ผูกตัวฟังบน element **ภายใน `host`** — ถูกเก็บไปพร้อม DOM เอง ไม่ต้องถอนใน `onUnload`
- โยน error ใน `render` = ถูกจับและจดลง Log แผงว่างเปล่า
- แผงยังไม่ถูกเปิดเองหลังลงทะเบียน — เรียก `showPanel` เมื่อผู้ใช้สั่ง

แผงของปลั๊กอินผนึก ลอย รวมแท็บ ได้เหมือนแผงในตัว · ปลั๊กอินถูกปิด/ถอน → แผงถูกปิดและถอนทะเบียนให้เอง

### `k2.showPanel(id)` · `k2.hidePanel(id)`

เปิด/ปิดแผงของปลั๊กอิน**ตัวเอง** — ส่ง `id` ตัวเดียวกับที่ให้ `registerPanel` (ไม่ต้องใส่คำนำหน้า)

```js
k2.registerCommand('เปิดแผงของฉัน', () => k2.showPanel('main'));
```

> อย่าเปิดแผงเองตอนโหลดหรือตอนเกิดเหตุการณ์ — แผงที่โผล่มาเองรบกวนการเขียน ให้ผู้ใช้เป็นคนสั่งเปิด (โปรแกรมจำไว้ให้ว่าแผงเคยเปิดอยู่)

## 3.5 เหตุการณ์

รายละเอียดของเหตุการณ์และวงจรชีวิตอยู่ที่ [บทที่ 4](04-hooks-lifecycle.md) — ส่วนนี้คือลายเซ็นของฟังก์ชัน

### `k2.on(event, handler)` → `() => void` 🔄

ฟังเหตุการณ์ · คืนฟังก์ชันสำหรับเลิกฟัง

| พารามิเตอร์ | |
|---|---|
| `event` | ชื่อเหตุการณ์ — ของโปรแกรม (`project:open` · `project:close` · `tab:activate` · `tab:save` · `plugins:loaded`) · ของปลั๊กอิน · หรือ `'*'` = ทุกเหตุการณ์ |
| `handler` | `(payload, eventName) => void` — อาร์กิวเมนต์ที่สองคือชื่อเหตุการณ์ (มีประโยชน์กับ `'*'`) |

```js
const off = k2.on('tab:save', (e) => k2.log('saved ' + e.title));
off();                                              // เลิกฟัง

k2.on('*', (payload, name) => k2.log(name));        // ดูทุกเหตุการณ์ (ไว้ดีบัก)
```

- ส่ง `handler` ที่ไม่ใช่ฟังก์ชัน = ไม่ทำอะไร (คืนฟังก์ชันเปล่า)
- handler ที่โยน error **ไม่กระทบตัวรับอื่น** — ถูกจดลง Log
- handler ถูกเรียกแบบ **ซิงก์** ในจังหวะที่เกิดเหตุการณ์ — ทำงานหนักในนั้น = โปรแกรมหน่วง ให้ `setTimeout`/`await` ออกไปทำทีหลัง
- handler แบบ `async` ใช้ได้ แต่โปรแกรม **ไม่รอ** ให้เสร็จ และ error ใน Promise ไม่ถูกจับให้ — ครอบ `try/catch` เอง

### `k2.off(event, handler)`

เลิกฟังด้วย handler ตัวเดิม (ทางเลือกของฟังก์ชันที่ `on` คืน)

### `k2.emit(event, data)` → `number`

ส่งเหตุการณ์ถึงทุกปลั๊กอิน (รวมตัวเอง) · คืนจำนวนตัวรับที่ถูกเรียกสำเร็จ

```js
k2.emit(k2.pluginName + ':done', { minutes: 25 });
```

- ตั้งชื่อ `<ชื่อปลั๊กอิน>:<เรื่อง>` เสมอ — **ห้ามส่งเหตุการณ์ชื่อของโปรแกรม** (`tab:save` ฯลฯ) ปลั๊กอินอื่นจะเข้าใจผิดว่าเกิดขึ้นจริง
- `data` ควรเป็นข้อมูลล้วน (แปลงเป็น JSON ได้) — อย่าส่ง DOM/ฟังก์ชัน/`EditorView`

### `k2.onUnload(fn)` → `boolean` 🔄

ลงตัวเก็บกวาด — `fn(why)` ถูกเรียกเมื่อปลั๊กอินกำลังถูกถอด

| `why` | เมื่อ |
|---|---|
| `'remove'` | ถูกปิด · ถอน · โฟลเดอร์หายไป · ผลงานที่พาปลั๊กอินมาถูกปิด |
| `'reload'` | ไฟล์เปลี่ยน กำลังจะถูกแทนด้วยรุ่นใหม่ (ตัวใหม่จะรันต่อทันที) |
| `'error'` | โค้ดโยน error ระหว่างรันครั้งแรก (ตัวเก็บกวาดที่ลงไว้ก่อนจุดพังถูกเรียก) |

- ลงได้หลายตัว — ถูกเรียก **ย้อนลำดับ** ที่ลง (ตัวที่ลงทีหลังถูกเรียกก่อน)
- **โยน error ในตัวเก็บกวาด = โปรแกรมถือว่าเก็บไม่ครบ** → แจ้งผู้ใช้ให้เริ่มโปรแกรมใหม่ แม้ประกาศ `hotReload`
- ทำงานแบบซิงก์และ **ไม่รอ Promise** — เก็บกวาดให้เสร็จในจังหวะเดียว

## 3.6 ไฟล์ของผลงาน

ทุกฟังก์ชันรับ **ทางสัมพัทธ์จากรากของผลงาน** ใช้ `/` คั่น เช่น `'Wiki/characters/โทระ.json'` · `'Reports/out.md'` · `'.'` = รากผลงาน

| กติกาของทาง | ผล |
|---|---|
| `\` ถูกแปลงเป็น `/` · `/` นำหน้าถูกตัด | `'/Memos/a.md'` = `'Memos/a.md'` |
| มีส่วน `..` | **ถูกปฏิเสธ** + จดคำเตือนลง Log |
| ยังไม่มีผลงานเปิด | ถูกปฏิเสธ |

"ถูกปฏิเสธ" = `readFile` คืน `null` · `writeFile` คืน `false` · `listDirs`/`listFiles` คืน `[]`

### `k2.readFile(rel)` → `Promise<string | null>` ⏳

อ่านไฟล์เป็นข้อความ UTF-8

- `null` = ทางถูกปฏิเสธ (ดูตารางข้างบน)
- ⚠ **ไฟล์ไม่มี = Promise ถูก reject** (โยน error) — ไม่ได้คืน `null` และโปรแกรมจดข้อผิดพลาดลง Log ทุกครั้ง → **ถามว่าไฟล์มีไหมด้วย `listFiles` ก่อน** หรือครอบ `try/catch`
- ไฟล์ที่ขึ้นต้นด้วย BOM: ได้ BOM ติดมาด้วย — ตัดเองก่อน `JSON.parse`
- **ข้อความเท่านั้น** — อ่านไฟล์ไบนารี (รูป · zip · ฟอนต์) ทางนี้ได้ไบต์ที่เสีย

```js
async function hasFile(rel) {
  const i = rel.lastIndexOf('/');
  const names = await k2.listFiles(i < 0 ? '.' : rel.slice(0, i));
  return names.includes(i < 0 ? rel : rel.slice(i + 1));
}
async function readJson(rel) {
  if (!(await hasFile(rel))) return null;
  const txt = await k2.readFile(rel);
  try { return JSON.parse(txt.charCodeAt(0) === 0xFEFF ? txt.slice(1) : txt); } catch { return null; }
}
```

### `k2.writeFile(rel, text)` → `Promise<boolean>` ⏳

เขียนข้อความลงไฟล์ (สร้างใหม่หรือ **เขียนทับทั้งไฟล์**)

- เขียนแบบ atomic (ไฟล์ชั่วคราวแล้วสลับชื่อ) — ไฟดับกลางคันไม่ได้ไฟล์ครึ่งเดียว
- **โฟลเดอร์ที่ยังไม่มีถูกสร้างให้**
- การเขียนถูกจดลง **ประวัติการทำงาน** ของผลงาน — ผู้ใช้ย้อนกลับได้จากแผงประวัติการทำงาน
- `text` ถูกแปลงเป็นสตริง · `false` = ทางถูกปฏิเสธ · เขียนไม่ได้จริง (ดิสก์เต็ม · ถูกล็อก) = Promise ถูก reject
- **ไม่มี API ลบ/ย้าย/เปลี่ยนชื่อไฟล์** — โดยเจตนา
- ⚠ **อย่าเขียนทับไฟล์งานของผู้ใช้** (ฉาก `.md` · `scenes.json` · `draft.json` · `section.json` · `project.khn.json`) — ดู [บทที่ 6](06-data-and-files.md#63-ไฟล์ที่ห้ามเขียนทับ)

### `k2.listDirs(rel)` → `Promise<string[]>` ⏳

**ชื่อ** ของโฟลเดอร์ย่อยชั้นเดียวใน `rel` (ไม่ใช่ทางเต็ม · ไม่ลงลึก) · โฟลเดอร์ไม่มี = `[]`

### `k2.listFiles(rel, ext?)` → `Promise<string[]>` ⏳

**ชื่อ** ของไฟล์ชั้นเดียวใน `rel` · `ext` = กรองด้วยส่วนท้ายของชื่อ เช่น `'.md'` `'.json'` (ตรงตัวพิมพ์) · โฟลเดอร์ไม่มี = `[]`

ทั้งสองตัวกรองไฟล์ขยะของระบบออกให้ (เช่น `._ชื่อ` ของ macOS · ไฟล์ชั่วคราวของโปรแกรม) · ลำดับในรายการตามระบบไฟล์ — เรียงเองถ้าลำดับสำคัญ

```js
// เดินทั้งต้นไม้ (ระวังโฟลเดอร์ใหญ่: Backups/ Snapshots/ .k2history/ Recycle/)
const SKIP = new Set(['Backups', 'Snapshots', '.k2history', 'Recycle', 'Plugins']);
async function walk(dir, out = []) {
  for (const f of await k2.listFiles(dir, '.md')) out.push(dir === '.' ? f : dir + '/' + f);
  for (const d of await k2.listDirs(dir)) if (!SKIP.has(d)) await walk(dir === '.' ? d : dir + '/' + d, out);
  return out;
}
```

## 3.7 ค่าตั้งของปลั๊กอิน

เก็บใน `project.khn.json → settings.plugins["<ชื่อโฟลเดอร์>"]` — **เป็นของผลงาน**: คนละผลงานคนละค่า และไปกับโฟลเดอร์ผลงาน

### `k2.getSettings(key?, def?)`

| เรียก | ได้ |
|---|---|
| `getSettings('key', def)` | ค่าของ `key` · ไม่มี = `def` |
| `getSettings()` | สำเนาของค่าตั้งทั้งก้อน (object) |

### `k2.setSettings(key, value)` · `k2.setSettings(object)` → `true`

เขียนค่า (รวมกับของเดิม) — บันทึกลงไฟล์ผลงานแบบหน่วงเล็กน้อย

```js
const opts = { minutes: 25, sound: true, ...k2.getSettings() };     // ค่าเริ่มต้น + ค่าที่ผู้ใช้ตั้ง
k2.setSettings('minutes', 30);
k2.setSettings({ minutes: 30, sound: false });                      // หลายค่าพร้อมกัน
```

ข้อควรรู้:

- เก็บได้เฉพาะ **ของที่แปลงเป็น JSON ได้** · เก็บให้เล็ก (ไฟล์นี้ถูกอ่านเขียนบ่อย) — ข้อมูลก้อนใหญ่ให้เขียนเป็นไฟล์ของตัวเองด้วย `writeFile`
- ⚠ **ห้ามเก็บความลับ** (คีย์ API · โทเคน · รหัสผ่าน) — ไฟล์ผลงานถูกส่งต่อ/สำรอง/เข้า Git
- ⚠ **ห้ามเก็บทางเต็มของเครื่อง** (`C:\Users\…`) — แปลงเป็นทางสัมพัทธ์จากรากผลงานก่อน
- ไม่มีผลงานเปิด: ค่าอยู่แค่ในหน่วยความจำ
- **ค่าระดับผู้ใช้** (ใช้ร่วมทุกผลงาน): ใช้ `localStorage` ด้วยคีย์ที่มีคำนำหน้า

  ```js
  const KEY = 'k2-plugin-' + k2.pluginName + ':prefs';
  const prefs = JSON.parse(localStorage.getItem(KEY) || '{}');
  localStorage.setItem(KEY, JSON.stringify({ ...prefs, minutes: 30 }));
  ```

  (`localStorage` อยู่ในโฟลเดอร์ข้อมูลผู้ใช้ของเครื่องนั้น · ไม่ถูกลบเมื่อถอนปลั๊กอิน — ลบเองถ้าต้องการ)
- ถอนปลั๊กอินแล้ว ค่าตั้งในไฟล์ผลงาน **ไม่ถูกลบ** (ติดตั้งกลับแล้วค่าเดิมยังอยู่)

## 3.8 หน้าจอ

### `k2.setStatus(text)`

ข้อความบนแถบสถานะ (ซ้ายล่าง) — หายเองในไม่กี่วินาที · อ่านออกเสียงโดยโปรแกรมอ่านจอ

- ใช้บอก **ผลของสิ่งที่ผู้ใช้เพิ่งสั่ง** — สั้น หนึ่งบรรทัด
- ข้อความถูกแทนด้วยข้อความถัดไปทันที — ใน handler ของ `tab:save` ข้อความของคุณจะถูกข้อความ "บันทึกแล้ว" ของโปรแกรมทับ ([4.1](04-hooks-lifecycle.md#tabsave))
- อย่าใช้รายงานความคืบหน้าถี่ ๆ และอย่าเขียนทับตอนผู้ใช้ไม่ได้สั่งอะไร

### `k2.ask(title, options?)` → `Promise<string | null>` ⏳

กล่องถามข้อความหนึ่งช่อง

| `options` | ค่าเริ่มต้น | |
|---|---|---|
| `value` | `''` | ค่าตั้งต้นในช่อง (ถูกเลือกทั้งหมดให้พิมพ์ทับ) |
| `placeholder` | `''` | คำใบ้ในช่องว่าง |
| `okLabel` | ป้ายตกลงของโปรแกรม | ป้ายปุ่มหลัก |
| `allowEmpty` | `false` | `true` = กดตกลงตอนช่องว่างได้ (คืน `''`) |
| `multiline` | `false` | ช่องหลายบรรทัด — `Enter` ขึ้นบรรทัดใหม่ · `Ctrl+Enter` = ตกลง |

คืนข้อความที่ **ตัดช่องว่างหัวท้ายแล้ว** · `null` = ผู้ใช้ยกเลิก (ปุ่มยกเลิก · `Esc` · คลิกนอกกล่อง) **หรือกดตกลงตอนช่องว่าง** (เมื่อ `allowEmpty` ไม่ได้เปิด)

```js
const name = await k2.ask('ชื่อแท็กใหม่', { placeholder: 'เช่น บู๊' });
if (name == null) return;                      // ยกเลิก
```

### `k2.confirmBox(title, okLabel?)` → `Promise<boolean>` ⏳

กล่องยืนยัน — ปุ่มยกเลิก + ปุ่มหลัก (ป้าย `okLabel` · ค่าเริ่มต้นคือ "ลบ" และปุ่มเป็นสไตล์อันตราย) → `true` เมื่อกดปุ่มหลัก

- **ส่ง `okLabel` เสมอ** ให้ตรงกับสิ่งที่จะเกิด (`'เขียนทับ'` · `'ส่งออก'`) — ไม่อย่างนั้นปุ่มจะเขียนว่า "ลบ"
- ข้อความขึ้นบรรทัดใหม่ด้วย `\n` ได้

### `k2.alertBox(text)` → `Promise<boolean>` ⏳

กล่องแจ้งข้อความ และเขียนข้อความเดียวกันลงแถบสถานะ

> **พฤติกรรมของรุ่น alpha.169**: ตัวนี้ใช้กล่องยืนยันตัวเดียวกับ `confirmBox` — มีปุ่มยกเลิกกับปุ่มหลักที่ป้ายเขียนว่า "ปลั๊กอิน" ไม่ใช่ปุ่ม "ตกลง" เดี่ยว ๆ · สำหรับข้อความสั้นที่ไม่ต้องให้ผู้ใช้ตอบ ใช้ `k2.setStatus` · ต้องการกล่องที่ป้ายปุ่มถูก ใช้ `k2.confirmBox(text, 'ตกลง')`

### `k2.menuPopup(items, x?, y?)`

เปิดเมนูป๊อปอัปที่พิกัดของหน้าต่าง (ค่าเริ่มต้น 80, 80) — เมนูปิดเองเมื่อเลือกหรือคลิกที่อื่น รองรับ `↑` `↓` `Enter` `Esc`

`items` = อาร์เรย์ของ object หรือ `'-'` (เส้นคั่น):

| ช่อง | ชนิด | |
|---|---|---|
| `text` | `string` | ป้ายแบบ **ข้อความล้วน** — ใช้ตัวนี้เสมอเมื่อมีข้อความจากผู้ใช้/ไฟล์ |
| `label` | `string` | ป้ายแบบ **HTML** ⚠ — ใช้ได้เฉพาะสตริงที่คุณเขียนเองทั้งหมด |
| `click` | `() => void` | ทำเมื่อเลือก |
| `disabled` | `boolean` | แถวหัวข้อ/กดไม่ได้ |
| `checked` | `boolean` | แสดงเครื่องหมายถูก (กำหนดค่า = เป็นรายการแบบติ๊ก) |
| `danger` | `boolean` | สีอันตราย |
| `swatch` | `string` | ช่องสีท้ายแถว (รหัสสี · `''` = ไม่มีสี) |
| `sub` | `() => items[]` | เมนูย่อย — **ต้องเป็นฟังก์ชัน** ที่คืนรายการ |
| `title` | `string` | ทูลทิป |

```js
button.onclick = (ev) => {
  const r = button.getBoundingClientRect();
  k2.menuPopup([
    { text: 'ตัวเลือก ก', click: () => pick('a') },
    { text: 'ตัวเลือก ข', checked: current === 'b', click: () => pick('b') },
    '-',
    { text: 'เพิ่มเติม', sub: () => [{ text: 'ย่อย 1', click: more }] },
    { text: 'ล้างค่า', danger: true, click: reset },
  ], r.left, r.bottom + 4);
};
```

> ⚠ **`label` ถูกใส่เป็น HTML** — ชื่อฉาก ชื่อตัวละคร หรือข้อความใดที่มาจากผู้ใช้/ไฟล์/เครือข่าย ต้องใช้ `text` ไม่อย่างนั้นข้อความที่มี `<` จะกลายเป็นแท็ก (ช่องโหว่ XSS)

### `k2.log(...args)`

เขียนบรรทัดระดับ info ลง **บันทึกการทำงานของโปรแกรม** (แผง Log + ไฟล์รายวันในเครื่องผู้ใช้) ขึ้นต้นด้วย `[plugin <ชื่อ>]` — อาร์กิวเมนต์ถูกแปลงเป็นสตริงแล้วต่อด้วยช่องว่าง

- object ต้อง `JSON.stringify` เอง (ไม่อย่างนั้นได้ `[object Object]`)
- ⚠ **อย่า log เนื้อหาของผลงาน ความลับ หรือลิงก์ที่มีคีย์** — ผู้ใช้อาจคัดลอก Log ไปแปะในรายงานบั๊กสาธารณะ
- log เท่าที่จำเป็น — บรรทัดเยอะทำให้ของจริงจม

## 3.9 เครือข่าย

### `k2.fetch(url, options?)` → `Promise<FetchResult>` ⏳

เรียก HTTP ผ่านตัวโปรแกรม (ไม่ติด CORS)

| `options` | |
|---|---|
| `method` | `'GET'` (ค่าเริ่มต้น) · `'POST'` · … |
| `headers` | object ของส่วนหัว |
| `body` | สตริง (เช่น `JSON.stringify(…)`) |

ผลลัพธ์ **ไม่โยน error** — ดูที่ `ok`:

| ช่องของผล | |
|---|---|
| `ok` | `true` เมื่อสถานะ 2xx |
| `status` | รหัส HTTP · `0` = ไปไม่ถึงเซิร์ฟเวอร์ |
| `body` | เนื้อคำตอบเป็น **ข้อความ** เสมอ — แปลงเอง: `JSON.parse(r.body)` |
| `error` | (เมื่อล้ม) สาเหตุสั้น ๆ เช่น `fetch failed` · `timeout 180000ms` — รายละเอียด (เช่น `ENOTFOUND` · `ECONNREFUSED`) อยู่ใน `body` |
| `netError` | `true` = ล้มที่ระดับเครือข่าย (ไม่มีเน็ต · หาโฮสต์ไม่เจอ · ใบรับรองผิด) |
| `timedOut` · `aborted` | หมดเวลา (ค่าเริ่มต้น 3 นาที) |

```js
const r = await k2.fetch('https://api.example.com/v1/items', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ q: 'คำค้น' }),
});
if (!r.ok) { k2.setStatus('เรียกไม่สำเร็จ (' + (r.status || r.error) + ')'); return; }
let data; try { data = JSON.parse(r.body); } catch { k2.setStatus('คำตอบไม่ใช่ JSON'); return; }
```

- **ข้อความเท่านั้น** — ดาวน์โหลดไฟล์ไบนารี (รูป · zip) ไม่ได้
- ไม่มีการสตรีม ได้คำตอบทั้งก้อนเมื่อจบ
- คำขอวิ่งจากเครื่องผู้ใช้โดยตรง — **บอกผู้ใช้ให้ชัดว่าปลั๊กอินส่งอะไรออกไปที่ไหน** ([บทที่ 7](07-security.md#74-ข้อปฏิบัติของผู้เขียนปลั๊กอิน))
- `fetch` ของเบราว์เซอร์ (`window.fetch`) ก็มี แต่ติด CORS กับเซิร์ฟเวอร์ส่วนใหญ่ — ใช้ `k2.fetch`

## 3.10 สิ่งที่ `k2` ไม่มี (ในรุ่นนี้)

| อยากทำ | สถานะ | ทางเลือก |
|---|---|---|
| เรียกคำสั่งของโปรแกรม (เปิดแผงในตัว · บันทึก · ส่งออก) | ไม่มีใน `k2` | — (ชื่อภายในเปลี่ยนได้ทุกรุ่น อย่าเรียกเอง) |
| เปิดไฟล์/ฉากเป็นแท็บ | ไม่มี | บอกผู้ใช้ให้เปิดเอง |
| รู้ว่าผู้ใช้เลือกข้อความเปลี่ยน / พิมพ์ | ไม่มีเหตุการณ์ | `getEditorView()` + ตรวจเมื่อผู้ใช้สั่ง · หรือ polling แบบเบา ๆ (อย่าลืมเก็บกวาด) |
| เพิ่มรายการในเมนูคลิกขวาของเอกสาร/Explorer | ไม่มี | คำสั่ง + คีย์ลัด |
| เพิ่มปุ่มบนแถบเครื่องมือ/แถบรูปแบบ | ไม่มี (มีปุ่มรวม "คำสั่งจากปลั๊กอิน") | แผงของปลั๊กอิน |
| เพิ่มรูปแบบส่งออก / ขั้นของเวิร์กโฟลว์ | ไม่มี | เขียนไฟล์เองด้วย `writeFile` · ผู้ใช้ใช้ขั้น "JavaScript เอง" ([10.5](10-other-extension-points.md#105-เวิร์กโฟลว์ส่งออก-และโค้ดสั้น)) |
| ลบ/ย้ายไฟล์ · อ่านไฟล์นอกผลงาน · ไฟล์ไบนารี | ไม่มี | — |
| เรียก AI ของผู้ใช้ | ไม่มี | `k2.fetch` ไปยังบริการที่ผู้ใช้กรอกคีย์ให้ปลั๊กอินเอง |
| ค่าตั้งระดับผู้ใช้ | ไม่มี | `localStorage` |
| ข้อความหลายภาษา | ไม่มีตัวช่วย | ตารางข้อความของปลั๊กอินเอง ([5.6](05-ui-guidelines.md#56-หลายภาษา)) |

> ตัวแปรอื่นบน `window` (เช่น `kapi`) มองเห็นได้จากโค้ดของปลั๊กอิน แต่ **ไม่ใช่ส่วนของ SDK** — ไม่มีเอกสาร เปลี่ยนได้ทุกรุ่นโดยไม่แจ้ง และข้ามกติกาความปลอดภัยของ `k2` (เช่น ขอบเขตโฟลเดอร์ผลงาน) ปลั๊กอินที่ใช้จะพังเงียบเมื่อโปรแกรมอัปเดต และจะไม่ผ่านเกณฑ์ของรายการแนะนำ ([บทที่ 9](09-store-submission.md))
