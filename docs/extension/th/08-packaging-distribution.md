# 8. แพ็กเกจและการแจกจ่าย

**ภาษา:** ไทย · [English](../en/08-packaging-distribution.md)

[← 7. ความปลอดภัยและความไว้วางใจ](07-security.md) · [ภาพรวม](README.md) · ถัดไป: [9. การเผยแพร่ และ "ร้านปลั๊กอิน" →](09-store-submission.md)

---

"แพ็กเกจ" ของปลั๊กอิน Killian 2 คือ **โฟลเดอร์ที่มี `plugin.json` กับไฟล์ JavaScript ที่รันได้เลยหนึ่งไฟล์** — ไม่มีรูปแบบไฟล์พิเศษ ไม่มีขั้น "build แพ็กเกจ" ของโปรแกรม
การแจกจ่ายคือการทำให้ผู้ใช้ได้โฟลเดอร์นั้น: ผ่าน **ลิงก์ GitHub** (โปรแกรมโหลดให้) · **ไฟล์ zip** · หรือ **วางไว้ในโฟลเดอร์ผลงาน**

## 8.1 สิ่งที่ตัวติดตั้งของโปรแกรมทำ

เมื่อผู้ใช้กด **ติดตั้งจากลิงก์** ในแผงปลั๊กอิน:

```
1. แปลงสิ่งที่วางมาเป็นที่อยู่ของ zip
     https://github.com/user/repo               → ลอง branch main แล้ว master
     https://github.com/user/repo/tree/dev      → branch dev
     https://github.com/user/repo/tree/dev/sub  → branch dev + โฟลเดอร์ย่อย sub
     user/repo                                  → เหมือนบรรทัดแรก
     https://…/x.zip                            → ไฟล์นั้นตรง ๆ (http/https เท่านั้น)

2. ดาวน์โหลด zip (เพดาน 25 MB)
     GitHub: จาก codeload.github.com/<user>/<repo>/zip/refs/heads/<branch>

3. หา "รากของปลั๊กอิน" ในซิป
     = โฟลเดอร์ของ plugin.json ที่ "ตื้นที่สุด"
     (ระบุโฟลเดอร์ย่อยมา → จำกัดอยู่ในโฟลเดอร์ที่ลงท้ายด้วยชื่อนั้น)

4. คัดไฟล์: เฉพาะที่อยู่ใต้รากของปลั๊กอิน
     ตัดทิ้ง: .git/  .github/  node_modules/  __MACOSX/  .DS_Store  Thumbs.db
     ปฏิเสธทางที่หลุดออกนอกโฟลเดอร์ปลายทาง

5. ตั้งชื่อโฟลเดอร์ปลายทาง
     = ชื่อโฟลเดอร์ที่ plugin.json อยู่
     อยู่รากรีโป → ชื่อรีโป ตัด "-main"/"-master" ท้ายออก
     อักขระที่ระบบไฟล์ไม่รับถูกตัด · ช่องว่าง → "-" · ยาวสุด 60

6. ถามผู้ใช้: "ติดตั้งลงโฟลเดอร์ <ชื่อ> — เขียนไฟล์ N ไฟล์" + คำเตือนเรื่องสิทธิ์
     มีโฟลเดอร์ชื่อเดิมอยู่ → ถามยืนยันเขียนทับอีกครั้ง

7. เขียนไฟล์ลง <ข้อมูลผู้ใช้>/Plugins/<ชื่อ>/  → โหลดปลั๊กอิน → ทำงานทันที
```

ผลต่อการออกแบบรีโปของคุณ:

| ข้อเท็จจริง | ทำอย่างนี้ |
|---|---|
| โปรแกรมโหลด **zip ของ branch** ไม่ใช่ไฟล์ของ Release | **ไฟล์ที่รันได้ต้องอยู่ใน branch** — ถ้า build จากหลายไฟล์ ต้อง commit ผล build (เช่น `main.js` หรือ `dist/main.js`) |
| ไม่ระบุ branch = ลอง `main` แล้ว `master` | branch หลักควรชื่อ `main` (หรือ `master`) และ **พร้อมใช้เสมอ** — งานที่ยังไม่เสร็จไว้ branch อื่น |
| ชื่อโฟลเดอร์ปลายทาง = ชื่อรีโป (เมื่อ `plugin.json` อยู่ราก) | **ชื่อรีโป = ตัวตนของปลั๊กอิน** — ตั้งให้ดีตั้งแต่แรก เปลี่ยนทีหลัง = ผู้ใช้ได้ปลั๊กอินตัวใหม่ |
| ⚠ ชื่อนั้นมาจาก **โฟลเดอร์ห่อของ zip** (`<รีโป>-<branch หรือ tag>`) และโปรแกรมตัดออกให้เฉพาะ `-main` / `-master` | `plugin.json` อยู่รากรีโป + ติดตั้งจาก branch อื่นหรือ zip ของ tag → ได้โฟลเดอร์ชื่อ `repo-dev` / `repo-1.3.0` = **ปลั๊กอินคนละตัว** กับที่ติดตั้งจาก main (ค่าตั้งไม่ตาม · อาจรันซ้อนสองตัว) → ถ้าจะแจกหลาย branch/tag ให้ใช้โครง **แบบ ข** (โฟลเดอร์ย่อยชื่อปลั๊กอิน) ซึ่งชื่อคงที่เสมอ |
| ติดตั้งทั้งโฟลเดอร์ที่ `plugin.json` อยู่ | เก็บให้เล็ก — ซอร์ส เทสต์ ภาพหน้าจอ ทำให้ซิปใหญ่และไฟล์ที่เขียนลงเครื่องผู้ใช้เยอะ (ดู [8.2](#82-โครงรีโปที่แนะนำ) แบบ ข) |
| ติดตั้งทับ = **เขียนไฟล์ทับ ไม่ได้ลบไฟล์เก่า** | อย่าพึ่งว่า "ไฟล์ที่ลบจากรีโปจะหายจากเครื่องผู้ใช้" — ไฟล์ที่รันคือ `entry` ตัวเดียว ไฟล์เก่าที่ค้างจึงไม่มีผล แต่ถ้าย้าย `entry` ให้เปลี่ยนในรุ่นเดียวกับ `plugin.json` |
| เพดาน 25 MB | ปลั๊กอินไม่ควรใหญ่ขนาดนั้น — ไม่ใส่ `node_modules` ไม่ใส่สื่อขนาดใหญ่ |
| ลงที่โฟลเดอร์ของผู้ใช้เสมอ | ถ้าต้องการให้เป็นของผลงาน ผู้ใช้ย้ายโฟลเดอร์เอง |

## 8.2 โครงรีโปที่แนะนำ

### แบบ ก — ไฟล์เดียว ไม่มี build (ง่ายสุด)

```
k2-word-count/                 ← ชื่อรีโป = ชื่อโฟลเดอร์ที่ติดตั้ง
├─ plugin.json
├─ main.js
├─ README.md
├─ LICENSE
└─ CHANGELOG.md
```

ลิงก์ติดตั้ง: `https://github.com/you/k2-word-count`

### แบบ ข — มีซอร์สหลายไฟล์ + build · แยกโฟลเดอร์ที่ติดตั้ง

```
k2-word-count/
├─ plugin/                     ← รากของปลั๊กอิน (สิ่งที่ผู้ใช้ได้)
│   ├─ plugin.json
│   └─ main.js                 ← ผล build — commit ไว้
├─ src/                        ← ซอร์ส (ไม่ถูกติดตั้ง)
│   ├─ index.js
│   └─ count.js
├─ test/
├─ package.json                ← สคริปต์ build ของคุณ (ไม่เกี่ยวกับโปรแกรม)
├─ README.md
└─ LICENSE
```

- โปรแกรมเลือก `plugin.json` ที่ตื้นที่สุด = `plugin/plugin.json` → ติดตั้งเฉพาะโฟลเดอร์ `plugin/`
- ⚠ ชื่อโฟลเดอร์ปลายทางจะเป็น **`plugin`** (ชื่อโฟลเดอร์ที่ `plugin.json` อยู่) ซึ่งชนกับของคนอื่นได้ — **ตั้งชื่อโฟลเดอร์นั้นเป็นชื่อปลั๊กอิน**:

```
k2-word-count/
├─ word-count/                 ← ชื่อนี้คือชื่อที่ติดตั้ง
│   ├─ plugin.json
│   └─ main.js
├─ src/ …
```

ลิงก์ติดตั้ง: `https://github.com/you/k2-word-count` (โปรแกรมหา `word-count/plugin.json` เอง)

### แบบ ค — หลายปลั๊กอินในรีโปเดียว

```
k2-plugins/
├─ word-count/   { plugin.json, main.js }
├─ focus-timer/  { plugin.json, main.js }
└─ README.md
```

- ลิงก์ต้องระบุโฟลเดอร์ย่อย: `https://github.com/you/k2-plugins/tree/main/word-count`
- ⚠ **อย่าวาง `plugin.json` ไว้รากรีโปด้วย** — ตัวที่ตื้นที่สุดจะชนะเมื่อผู้ใช้ไม่ระบุโฟลเดอร์
- ถ้าไม่ระบุโฟลเดอร์ย่อยและมีหลายตัวลึกเท่ากัน โปรแกรมเลือกตัวแรกตามตัวอักษร — ให้ลิงก์เต็มใน README เสมอ

### ไฟล์ที่ควรมีในรีโป

| ไฟล์ | เนื้อหา |
|---|---|
| `README.md` | ทำอะไร · ภาพหน้าจอ · **ลิงก์ติดตั้ง** · วิธีใช้ · สิทธิ์และข้อมูล ([7.5](07-security.md#75-สิ่งที่ผู้เขียนควรบอกผู้ใช้-ใน-readme)) · รุ่น Killian ที่รองรับ · ช่องทางรายงานปัญหา — แม่แบบที่ [9.5](09-store-submission.md#95-แม่แบบ-readme-ของปลั๊กอิน) |
| `LICENSE` | สัญญาอนุญาตของโค้ดคุณ (MIT · ISC · Apache-2.0 …) — ไม่มี = คนอื่นไม่มีสิทธิ์ใช้/แก้/แจกต่อตามกฎหมาย |
| `CHANGELOG.md` | รุ่นไหนเปลี่ยนอะไร — ผู้ใช้อัปเดตด้วยมือ ต้องรู้ว่าคุ้มไหม |
| `.gitignore` | `node_modules/` (แต่ **ไม่** ignore ผล build ที่ต้องติดตั้ง) |

## 8.3 หลายไฟล์ · TypeScript: bundle เป็นไฟล์เดียว

โปรแกรมรันไฟล์ entry ด้วย `new Function('k2', โค้ด)` — ไม่มี `import`/`require` ซอร์สหลายไฟล์ต้องถูกรวมเป็นไฟล์เดียวแบบ **IIFE** ก่อน

### esbuild (แนะนำ — เร็ว ตั้งค่าน้อย)

```bash
npm init -y
npm install --save-dev esbuild
```

`package.json` ของรีโปคุณ (โปรแกรมไม่อ่านไฟล์นี้):

```json
{
  "scripts": {
    "build": "esbuild src/index.js --bundle --format=iife --target=chrome120 --outfile=word-count/main.js",
    "watch": "esbuild src/index.js --bundle --format=iife --target=chrome120 --outfile=word-count/main.js --watch"
  }
}
```

```js
// src/index.js
import { countWords } from './count.js';       // import ระหว่างไฟล์ของคุณเอง — ได้
// k2 เป็นตัวแปรที่โปรแกรมส่งให้ตอนรัน — ใช้ได้เลย ไม่ต้อง import
k2.registerCommand('นับคำ', () => k2.setStatus(countWords(k2.getMarkdown()) + ' คำ'));
```

ข้อสำคัญ:

| ธง | ทำไม |
|---|---|
| `--bundle` | รวมทุก import เป็นไฟล์เดียว |
| `--format=iife` | ห่อเป็นฟังก์ชันที่รันทันที — ไม่มี `import`/`export` เหลือในผลลัพธ์ · `k2` ยังมองเห็นได้เพราะเป็นตัวแปรของขอบเขตนอก |
| `--target=chrome120` | โปรแกรมใช้ Chromium รุ่นใหม่ — ไม่ต้องแปลงไวยากรณ์ลงต่ำ |
| ไม่ใส่ `--platform=node` | ปลั๊กอินรันในเบราว์เซอร์ ไม่มี Node.js |
| ไลบรารีจาก npm | ใช้ได้ถ้าเป็นไลบรารีฝั่งเบราว์เซอร์ล้วน (ไม่พึ่ง `fs` `path` `process`) — ถูกรวมเข้าไฟล์ |
| `--minify` | **ไม่แนะนำ** — ผู้ใช้/ผู้รีวิวควรอ่านโค้ดที่จะรันได้ ขนาดไฟล์ไม่ใช่ปัญหา |
| `--sourcemap` | ไม่จำเป็น (โค้ดรันผ่าน `new Function` — source map ไม่ถูกจับคู่ให้) |

ระหว่างพัฒนา: ตั้ง `--outfile` ให้ชี้ **เข้าโฟลเดอร์ปลั๊กอินของผู้ใช้ตรง ๆ** (หรือทำ symlink/junction) แล้วใช้ `--watch` — แก้ซอร์ส → ไฟล์ถูก build → กด **โหลดใหม่** ในแผง

### TypeScript

```bash
npm install --save-dev esbuild typescript
```

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022", "module": "ESNext", "moduleResolution": "Bundler",
    "strict": true, "noEmit": true, "lib": ["ES2022", "DOM"]
  },
  "include": ["src", "k2.d.ts"]
}
```

1. คัดลอก [`k2.d.ts`](../k2.d.ts) ของคู่มือนี้ไปไว้ในรีโป — ประกาศตัวแปร `k2` และชนิดทั้งหมด
2. `esbuild src/index.ts --bundle --format=iife --target=chrome120 --outfile=word-count/main.js` (esbuild ตัดชนิดออกให้ ไม่ตรวจชนิด)
3. ตรวจชนิดแยก: `npx tsc --noEmit`

ไม่ใช้ TypeScript ก็ได้ประโยชน์จาก `k2.d.ts`: วางไว้ข้าง `main.js` แล้วใส่บรรทัดแรก

```js
/// <reference path="./k2.d.ts" />
// @ts-check
```

VS Code จะเติมโค้ดและเตือนชนิดของ `k2` ให้

### ไฟล์ข้อมูลประกอบ

ปลั๊กอินไม่มี API อ่านไฟล์ในโฟลเดอร์ของตัวเอง — รวมข้อมูลเข้า bundle:

```js
import words from './stopwords.json';          // esbuild รวม JSON ให้
import css from './style.css';                 // ต้องบอก loader: --loader:.css=text
import icon from './icon.svg';                 // --loader:.svg=text (ใช้เป็น innerHTML ของ element ที่คุณสร้างเอง — เนื้อไฟล์เป็นของคุณ ไม่ใช่ข้อมูลผู้ใช้)
```

รูปขนาดเล็ก: `--loader:.png=dataurl` · สื่อขนาดใหญ่ไม่ควรอยู่ในปลั๊กอิน

## 8.4 เลขรุ่น

ใช้ [Semantic Versioning](https://semver.org/lang/th/) ในช่อง `version` ของ `plugin.json`:

| เปลี่ยน | เพิ่ม | ตัวอย่าง |
|---|---|---|
| แก้บั๊ก ไม่เปลี่ยนพฤติกรรมที่ผู้ใช้พึ่ง | PATCH | `1.2.0` → `1.2.1` |
| เพิ่มความสามารถ ของเดิมยังใช้ได้ | MINOR | `1.2.1` → `1.3.0` |
| เปลี่ยนที่ทำให้ของเดิมใช้ไม่ได้ (รูปข้อมูลที่เก็บ · ชื่อเหตุการณ์ที่ส่ง · ถอดคำสั่ง · ขยับ `minAppVersion` ข้ามรุ่นหลัก) | MAJOR | `1.3.0` → `2.0.0` |
| ยังไม่นิ่ง | `0.x.y` | `0.4.0` |

- โปรแกรม **แสดง** `version` บนการ์ด แต่ **ไม่ใช้เทียบ** อะไร (ไม่มีการอัปเดตอัตโนมัติ) — เลขรุ่นมีไว้ให้ผู้ใช้กับคุณคุยกันรู้เรื่อง
- ทุกรุ่นที่ปล่อย: แก้ `version` → เขียน CHANGELOG → commit → **ติด tag** (`v1.3.0`) → push · tag ทำให้ผู้ใช้ติดตั้งรุ่นเจาะจงได้ผ่านลิงก์ zip ของ tag: `https://github.com/you/repo/archive/refs/tags/v1.3.0.zip` (ใช้ได้ถูกต้องเมื่อ `plugin.json` อยู่ในโฟลเดอร์ย่อยชื่อปลั๊กอิน — ดูคำเตือนเรื่องชื่อโฟลเดอร์ห่อใน [8.1](#81-สิ่งที่ตัวติดตั้งของโปรแกรมทำ))
- `minAppVersion`: ตั้งเป็นรุ่นต่ำสุดที่คุณ **ทดสอบจริง** — ขยับเมื่อใช้ API ใหม่ ([2.2](02-anatomy.md#การเทียบ-minappversion) มีข้อจำกัดของการเทียบในช่วง alpha)

### เปลี่ยนรูปของข้อมูลที่เก็บ

ค่าที่เก็บด้วย `setSettings` อยู่ในไฟล์ผลงานของผู้ใช้ข้ามรุ่นของปลั๊กอิน:

```js
const DATA_VERSION = 2;
let data = k2.getSettings('data', null);
if (data && (data.v || 1) < DATA_VERSION) data = migrate(data);     // อ่านของเก่าได้เสมอ
function migrate(d) {
  if ((d.v || 1) === 1) d = { v: 2, items: (d.list || []).map((x) => ({ name: x, done: false })) };
  return d;
}
```

- ใส่เลขรุ่นของข้อมูล (`v`) ตั้งแต่รุ่นแรก
- รุ่นใหม่ต้องอ่านของรุ่นเก่าได้ · เขียนกลับเป็นรูปใหม่เมื่อมีการแก้ครั้งแรก
- ผู้ใช้อาจย้อนไปรุ่นเก่า — อย่าลบช่องที่รุ่นเก่าต้องใช้ถ้าเลี่ยงได้

## 8.5 ช่องทางแจกจ่าย

| ช่องทาง | ผู้ใช้ทำ | เหมาะกับ |
|---|---|---|
| **รีโป GitHub สาธารณะ** | วางลิงก์รีโปใน "ติดตั้งจากลิงก์" | ทางหลัก — อัปเดตด้วยการติดตั้งลิงก์เดิมทับ |
| **zip ของ tag / Release** | วางลิงก์ `.zip` | ให้ผู้ใช้ตรึงรุ่นเจาะจง |
| **zip บนเว็บของคุณ** | วางลิงก์ `.zip` (ต้อง `https://` และลงท้าย `.zip`) | ไม่ใช้ GitHub |
| **ไฟล์ zip ส่งกันตรง ๆ** | แตกเองแล้ววางโฟลเดอร์ใน `Plugins/` → โหลดใหม่ | ทีมภายใน · ออฟไลน์ |
| **อยู่ในโฟลเดอร์ผลงาน** (`<ผลงาน>/Plugins/<ชื่อ>/`) | เปิดผลงาน → อนุญาต | เครื่องมือเฉพาะของผลงาน/ทีม — ไปกับ zip/Git ของผลงาน |

ข้อจำกัดของ "ติดตั้งจากลิงก์":

- รองรับ **GitHub** และ **ลิงก์ `.zip` ตรง ๆ** เท่านั้น (GitLab · Bitbucket · Codeberg: ใช้ลิงก์ดาวน์โหลด zip ของ branch/tag ที่ลงท้าย `.zip`)
- **รีโป private ติดตั้งจากลิงก์ไม่ได้** (โปรแกรมไม่ส่งข้อมูลรับรอง) — ใช้การวางโฟลเดอร์เอง
- ไฟล์ zip ต้องมี `plugin.json` — zip ของ "Source code" ที่ GitHub สร้างให้ใช้ได้

### ทำ zip เอง

```
word-count-1.3.0.zip
└─ word-count/
    ├─ plugin.json
    └─ main.js
```

- ชั้นบนของ zip เป็น **โฟลเดอร์ชื่อปลั๊กอิน** (ชื่อนี้จะเป็นชื่อโฟลเดอร์ที่ติดตั้ง) — ถ้าวาง `plugin.json` ไว้รากของ zip และติดตั้งผ่านลิงก์ zip ตรง ๆ ชื่อโฟลเดอร์จะตกไปเป็นค่าเริ่มต้น `plugin`
- ใช้ `/` ในทางของไฟล์ (เครื่องมือ zip ทั่วไปทำให้อยู่แล้ว)
- ไม่ใส่ `node_modules` · `.git` · ไฟล์ซ่อนของระบบ

## 8.6 อัปเดตปลั๊กอิน

**ไม่มีการอัปเดตอัตโนมัติและไม่มีการแจ้งเตือนรุ่นใหม่** — วงจรของรุ่นนี้คือ:

1. คุณ push รุ่นใหม่ขึ้น branch หลัก
2. ผู้ใช้กด **ติดตั้งจากลิงก์** ด้วยลิงก์เดิม → ยืนยันเขียนทับ
3. โปรแกรมเห็นว่าไฟล์เปลี่ยน → ถอดรุ่นเก่า (`onUnload('reload')`) → รันรุ่นใหม่ · ปลั๊กอินที่ไม่ประกาศ `hotReload` → ผู้ใช้ถูกแจ้งให้เริ่มโปรแกรมใหม่

สิ่งที่คุณทำได้เพื่อให้ผู้ใช้รู้ว่ามีรุ่นใหม่:

- ให้ผู้ใช้กด **Watch → Releases** ที่รีโป (GitHub ส่งอีเมลเมื่อออก Release)
- เขียนเลขรุ่นปัจจุบันไว้เด่น ๆ ใน README
- ⚠ **อย่าทำตัวเช็กรุ่นที่ติดต่อเน็ตเองเงียบ ๆ** ในปลั๊กอิน — ขัดกับหลัก "ไม่ส่งอะไรออกนอกเครื่องโดยผู้ใช้ไม่ได้สั่ง" ถ้าจะมี ให้เป็นคำสั่งที่ผู้ใช้กดเอง ("ตรวจรุ่นใหม่ของปลั๊กอินนี้") และบอกใน README

ทำให้การอัปเดตราบรื่น:

- ชื่อโฟลเดอร์/ชื่อรีโป **ต้องเหมือนเดิม** — เปลี่ยน = ผู้ใช้ได้ปลั๊กอินสองตัว และค่าตั้งเดิมไม่ตามไป
- รุ่นใหม่อ่านข้อมูลของรุ่นเก่าได้ ([8.4](#เปลี่ยนรูปของข้อมูลที่เก็บ))
- ประกาศ `hotReload` ถ้าเก็บกวาดครบ — ผู้ใช้อัปเดตแล้วใช้ต่อได้ทันที
- ใส่วิธีอัปเดตและวิธีย้อนรุ่น (ลิงก์ zip ของ tag ก่อนหน้า) ใน README

## 8.7 ถอนการติดตั้ง

ผู้ใช้กด **ถอนออก** บนการ์ด → โปรแกรมลบโฟลเดอร์ของปลั๊กอิน **ถาวร** (ไม่ลงถังขยะ)

| ถูกลบ | **ไม่** ถูกลบ |
|---|---|
| โฟลเดอร์ของปลั๊กอิน | ค่าตั้งใน `project.khn.json → settings.plugins[<ชื่อ>]` ของแต่ละผลงาน |
| | `localStorage` ที่ปลั๊กอินเขียน |
| | ไฟล์ที่ปลั๊กอินสร้างในผลงาน (`Reports/` · `PluginData/<ชื่อ>/`) |

ทำตัวให้ถอนสะอาด: บอกใน README ว่าปลั๊กอินทิ้งอะไรไว้ที่ไหน · ถ้าเหมาะ ให้มีคำสั่ง "ล้างข้อมูลของปลั๊กอินนี้" (ลบคีย์ `localStorage` และล้างค่า `setSettings` เป็นค่าว่าง — ปลั๊กอินลบไฟล์ไม่ได้ ให้บอกผู้ใช้ลบโฟลเดอร์เอง)

## 8.8 รายการตรวจก่อนปล่อยรุ่น

**แพ็กเกจ**

- [ ] `plugin.json` เป็น JSON ที่ถูกต้อง · มี `name` `version` `description` `author` `minAppVersion` `homepage`
- [ ] `entry` ชี้ไฟล์ที่มีจริงในโฟลเดอร์ปลั๊กอิน · ไม่มี `..`
- [ ] ไฟล์ entry รันได้เดี่ยว ๆ (ไม่มี `import`/`require` เหลือ) — ลองเปิดไฟล์ดู
- [ ] ผล build ถูก commit · branch หลักอยู่ในสภาพพร้อมใช้
- [ ] `version` ตรงกับ tag และ CHANGELOG
- [ ] ไม่มี `node_modules` · ไฟล์ทดสอบขนาดใหญ่ · ความลับ · ทางไฟล์ของเครื่องคุณ ในโฟลเดอร์ที่ติดตั้ง

**ทดสอบการติดตั้งจริง** (บนโปรไฟล์สะอาด — [11.4](11-debugging-testing.md#114-โปรไฟล์ทดสอบที่แยกจากของจริง))

- [ ] ติดตั้งจากลิงก์รีโปของตัวเอง → ชื่อโฟลเดอร์ถูก · จำนวนไฟล์สมเหตุผล · การ์ดขึ้น "ทำงานอยู่"
- [ ] ติดตั้งทับรุ่นก่อนหน้า → ทำงานต่อ ไม่มีของซ้ำสองชุด · ข้อมูลเดิมยังอ่านได้
- [ ] ปิด → เปิดใช้ · ถอน → ติดตั้งใหม่
- [ ] เปลี่ยนผลงาน · ไม่มีผลงานเปิด · ไม่มีเอกสารเปิด

**พฤติกรรม**

- [ ] รายการของ [5.10](05-ui-guidelines.md#510-รายการตรวจหน้าตา) (หน้าตา) และ [7.4](07-security.md#74-ข้อปฏิบัติของผู้เขียนปลั๊กอิน) (ความปลอดภัย)
- [ ] ถ้าประกาศ `hotReload`: หลังปิด ไม่มีตัวจับเวลา ตัวฟัง element สไตล์ ของปลั๊กอินเหลือ ([11.3](11-debugging-testing.md#113-ตรวจว่าเก็บกวาดครบ))
- [ ] แผง Log ไม่มีบรรทัด error/warn ของปลั๊กอินระหว่างใช้งานปกติ
