# แผน: รูปกลางย่อหน้า `abc ![](x.png) def` (alpha.164 · รอบต่อ 3 · งาน 4)

> สถานะ (alpha.164 · รอบต่อ 4): **รอบ A เสร็จ · รอบ B เสร็จส่วนตัวแปลง · รอบ C ยังไม่เริ่ม**
> · A: `parseInline` (RE_INLINE_IMG ที่เดียว) · โหนด `image` · `inlineImgMd` (ไฟล์เก่าไม่เปลี่ยนสักไบต์) · `resolved` ลึกทั้งต้นไม้ ·
>   บทภาพยนตร์คืนข้อความดิบ (`inlineImagesAsText`) — unit `md-inline-image` + e2e `[IMG-IN-A]`
> · B: `inlineHtml` ใช้ส่วนรูปจาก parseInline + `imgSrc` · กฎคู่แฝดใน `proseExportCss` · `inlineDisplayText` ไม่โชว์ไวยากรณ์รูป
>   (= ตัวประมาณของตัวแก้ไข) · ตัววัดจัดหน้า **ไม่ต้องแตะ** (ความสูงเป็นหน่วยบรรทัด ชิดล่าง → h=1 สูงเท่าบรรทัดปกติ — e2e วัดจริงแล้ว)
>   ยังไม่มี: e2e เทียบ "ช่องตัวอย่าง = ไฟล์จริง" ที่มีรูปในบรรทัด h=2/3 (จำนวนหน้า/จุดตัด)
> · C (ยังไม่ทำ): ตารางความเสี่ยงข้างล่างทีละแถว + UI แทรก/คลิกขวา (ตอนนี้ได้รูปในบรรทัดจากการพิมพ์/แก้ไฟล์เท่านั้น)
> ผู้ถามต่อ: อ่านหัวข้อ "ความเสี่ยง" ก่อน — ส่วนที่ยากไม่ใช่ schema แต่คือ **ตัวนับตำแหน่งข้อความ** ทั้งโปรแกรม

## ตอนนี้เป็นอย่างไร (สำรวจจากโค้ดจริง)

| ชั้น | ทำอะไรกับ `![alt](src)` กลางบรรทัด | ที่อยู่ |
|---|---|---|
| ตัวแก้ไข (schema) | **โชว์เป็นข้อความดิบ** — มีรูปแค่ระดับบล็อก (`figure`, atom) | `editor.js` `figure:` |
| md → doc | `RE_IMG` จับเฉพาะ "ทั้งบรรทัดเป็นรูป" → `figure` · กลางบรรทัดตกไปเป็น text | `md.js` `RE_IMG` · `inlineNodes()` |
| ไฟล์ส่งออก (HTML/PDF นิยาย) | **แสดงเป็นรูปแล้ว** — `inlineHtml()` แปลงเป็น `<img>` หลัง escape | `md.js` `inlineHtml()` ← `mdToHtmlBody()` |
| ช่องตัวอย่างส่งออก | ถอดเหลือคำบรรยาย (`inlineDisplayText` → `$1`) | `md.js` · `prose-format.js` `mdToProseBlocks()` |
| ข้อความล้วน / นับคำ / Navigation | ถอดเหลือคำบรรยาย (`inlinePlainText`) | `md.js` |

= ไฟล์ที่ส่งออก "เห็นรูป" แต่จอกับช่องตัวอย่าง "ไม่เห็น" → **ตัวอย่างไม่ตรงไฟล์จริง** (ผิดกฎ alpha.132r)
ข้อนี้เป็นเหตุผลที่ควรทำ แม้จะไม่ใช่งานเล็ก

## ออกแบบ

### 1. โหนด inline ใหม่ `image` (editor.js)
```js
image: { inline: true, group: 'inline', atom: true, draggable: false, selectable: true,
         attrs: { src: {}, alt: { default: '' }, resolved: { default: '' }, h: { default: 1 } },
         parseDOM: [{ tag: 'img.k-inline-img[data-src]', getAttrs: … }],
         toDOM: (n) => ['img', { class: 'k-inline-img', 'data-src': n.attrs.src, src: n.attrs.resolved || n.attrs.src, alt: n.attrs.alt }] }
```
- **ความสูงเป็นหน่วยบรรทัด** (`h` = 1 บรรทัด เริ่มต้น · สูงสุด 3) ไม่ใช่พิกเซล — ตัวจัดหน้าคิดเป็นบรรทัดได้ตรง
  และไม่ต้องรอรูปโหลดเพื่อรู้ความสูง (ต่างจาก `figure` ที่ต้อง `whenImagesReady`) · CSS: `height:calc(var(--line-h) * h); width:auto; vertical-align:text-bottom`
- ไม่มี `draggable` (บทเรียน alpha.143r — ลากเลือกข้อความข้ามรูปไม่ได้)
- `resolved` เติมที่เดียวกับ figure (`editor.js:1355` · `n.type === 'figure' || n.type === 'image'`)

### 2. md.js — ตัวอ่าน/ตัวเขียน **ที่เดียว**
- `parseInline()` เพิ่มคู่แข่งตัวใหม่ `RE_INLINE_IMG = /!\[([^\]\n]*)\]\(([^)\s]+)(?:\s+"([^"]*)")?\)/` → segment `{ image: {src, alt, opts} }`
  (แข่ง "ซ้ายสุดชนะ" กติกาเดียวกับสแปนสี) — **ห้ามเขียน regex ชุดที่สองที่อื่น** (inlineHtml/inlinePlainText/inlineDisplayText ใช้ผลจากตัวนี้)
- `inlineNodes()` : segment รูป → `{ type:'image', attrs }` · `inlineToMd()` : โหนด image → `![alt](src "h=2")`
- ตัวเลือกความสูงใช้ช่อง "ชื่อกำกับ" แบบเดียวกับ figure (`"fit=page w=60%"`) → v1 เปิดได้ (ยังเป็น markdown แท้)
- `RE_IMG` (ทั้งบรรทัด) **ยังชนะก่อน** — บรรทัดที่เป็นรูปล้วนยังเป็น `figure` เหมือนเดิม ไฟล์เก่าไม่เปลี่ยนความหมาย

### 3. ตัวแปลงหน้ากระดาษสองตัว (กฎถาวร alpha.132r — แก้คู่กันเสมอ)
- `mdToHtmlBody()` : ใส่ `class="k-inline-img"` + `style="height:<h>lh"` (มีอยู่แล้วครึ่งทาง — `inlineHtml`)
- `mdToProseBlocks()` : ย่อหน้าต้องพา **ชิ้นรูป** ไปด้วย (ตอนนี้คืน `text` สตริงเดียว) → เพิ่มช่อง `inlineImgs:[{at, src, h}]`
  แล้วตัววาดช่องตัวอย่าง (`renderProsePageView`) แทรก `<img>` ตามตำแหน่ง · `proseBlocksFromDoc()` คืนรูปแบบเดียวกัน
- โหมดขาวดำ: รูปไม่ถูกย้อม (เหมือน figure)

### 4. ตัววัดจัดหน้า (prose-measure.js)
- เพราะความสูงเป็นหน่วยบรรทัด → **ไม่ต้องรอรูปโหลด** · แต่บรรทัดที่มีรูป `h>1` สูงกว่าบรรทัดปกติ → ตัวนับบรรทัดของ
  `measureProseBlocks` ต้องวัดจาก DOM จริง (ทำอยู่แล้ว — ตัววัดใช้ `getClientRects` ของบรรทัด) → ตรวจว่าจุดตัดกลางย่อหน้า
  (`prosePosAtCut`) ไม่ตัดกลางรูป: atom inline เป็นตำแหน่งเดียว ไม่มีข้างใน — ตัดได้แค่ก่อน/หลัง
- `watchDocImages()` ไม่ต้องแตะ (ความสูงไม่ขึ้นกับการโหลด) แต่ยังต้องกันสำเนาใน `.ed-page-clip` ตามเดิม

### 5. คำสั่ง/UI
- ปุ่มแทรกรูป: เคอร์เซอร์อยู่ **กลางย่อหน้าที่มีข้อความ** = ถามว่า "ในบรรทัด / เป็นบล็อก" (หรือ Alt+คลิก = ในบรรทัด)
- คลิกขวาที่รูปในบรรทัด → ความสูง 1/2/3 บรรทัด · แปลงเป็นรูปบล็อก · ลบ
- บทภาพยนตร์ **ไม่รองรับ** (fountain ไม่มีรูปกลางบรรทัด · บทพิมพ์ตามธรรมเนียมไม่มี) — `SPEditor` ปฏิเสธคำสั่ง

## ความเสี่ยง (ส่วนที่กินเวลาจริง)

โหนด inline atom มี `textContent` = `''` แต่กินตำแหน่ง 1 หน่วยใน doc → ทุกที่ที่ "แปลงตำแหน่งข้อความ ↔ ตำแหน่ง doc"
ด้วยการนับอักษรจะคลาดไปหนึ่งหลังรูปทุกตัว · ต้องไล่ตรวจ (ใช้ `leafText` ของ `textBetween` = `'￼'` ช่วยได้):

| ที่ | ใช้ตำแหน่งอย่างไร |
|---|---|
| `nthTextPos` / `gotoSearchMatch` (ค้นหาทั้งโปรเจกต์) | นับอักษรจากเนื้อ .md → ตำแหน่ง doc |
| `spell.js` decoration · `mentionPlugin` (ลิงก์ Wiki) | เดิน text node — น่าจะรอด แต่ต้องมีเทส |
| `onset-diff` (เทียบฉบับหน้ากองถ่าย) | diff ระดับบล็อกจาก `textContent` — รูปที่เพิ่ม/ลบจะ **ไม่ถูกนับเป็นการแก้** |
| `text-case.js` · `caseTransform` | `nodesBetween` เฉพาะ text — รอด |
| `nav-model` `navKey` (สี/ดาวของแถว) | ผูกกับข้อความแถว — รอด |
| นับคำ / เวลาอ่าน | `countWords` ของ md — ต้องไม่นับ URL ของรูปเป็นคำ (ตอนนี้ถอดเหลือคำบรรยาย = นับคำบรรยาย) |
| `markdown-code-toggle` | ซ่อนรหัสนำหน้าบรรทัด — ไม่เกี่ยว |
| คัดลอก/วาง (clipboard HTML) | `<img>` จากเว็บวางเข้ามา = ต้องตัดสินว่าเป็น image inline หรือทิ้ง |
| ส่งออก DOCX/EPUB/RTF/FDX/txt | DOCX/EPUB ต้องฝังรูปในบรรทัด · RTF/FDX/txt = คำบรรยาย |

## ลำดับที่แนะนำ (แต่ละรอบปิดด้วย e2e ALL OK)

1. **รอบ A** — md.js (`parseInline` + `inlineNodes` + `inlineToMd`) + schema + `resolved` + unit round-trip
   (ไฟล์เก่าต้องออกมาเหมือนเดิมทุกไบต์ · `![](x)` ทั้งบรรทัดยังเป็น figure) + e2e: เปิดไฟล์ที่มีรูปกลางบรรทัด → เห็น `<img>` · บันทึกแล้วไฟล์ไม่เปลี่ยน
2. **รอบ B** — ตัวแปลงหน้ากระดาษสองตัว + ตัววัด + e2e เทียบ "ช่องตัวอย่าง = ไฟล์จริง" (จำนวนหน้า/ตำแหน่งตัด)
3. **รอบ C** — ตารางความเสี่ยงข้างบนทีละแถว (ค้นหา/กระโดด · onset · ส่งออก DOCX/EPUB) + UI แทรก/คลิกขวา

ประตูกันพลาดที่ต้องมี: unit `md-inline-image` (round-trip · ซ้ายสุดชนะกับสี/ตัวหนา · escape `"` ใน alt — บทเรียน H6) ·
e2e `[IMG-IN-*]` กดปุ่มจริง/วัดความสูงบรรทัดจริง
