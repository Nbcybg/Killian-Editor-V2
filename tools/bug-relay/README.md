# ตัวกลางรับรายงานบั๊ก (k2-bug-relay)

โปรแกรม Killian 2 ส่งรายงานบั๊กเข้าตัวกลางตัวนี้ → ตัวกลางเปิด Issue ในรีโปด้วยโทเคนของผู้ดูแล
ผู้ใช้จึงรายงานได้ **ตรงจากโปรแกรม** โดยไม่ต้องมีบัญชี GitHub และในโปรแกรมไม่มีโทเคนใด ๆ

**ตัวกลางไม่ใช่เครื่อง** — เป็นสคริปต์ไฟล์เดียว (`worker.js`) ที่ฝากรันบนคลาวด์ของ Cloudflare (Workers · แผนฟรี)
ออนไลน์ตลอด ไม่ต้องมีเครื่องหรือเซิร์ฟเวอร์ของเราเปิดทิ้งไว้ และไม่ต้องดูแลระบบปฏิบัติการอะไร

```
โปรแกรม ──POST /report──▶ Cloudflare Worker (ถือ GITHUB_TOKEN) ──▶ GitHub Issues ◀── ทุกคนเปิดดูได้
```

## ติดตั้งผ่านหน้าเว็บ (ครั้งเดียว · ราว 10 นาที · ฟรี · ไม่ต้องลงโปรแกรมอะไรในเครื่อง)

1. **สร้างโทเคนของ GitHub** — github.com → รูปโปรไฟล์ → Settings → Developer settings → Personal access tokens → *Fine-grained tokens* → Generate new token
   - Repository access: **Only select repositories** → เลือกรีโปของโปรแกรมรีโปเดียว
   - Permissions → Repository permissions → **Issues: Read and write** (อย่างอื่นไม่ต้องให้)
   - ตั้งวันหมดอายุ แล้วจดไว้ว่าต้องต่ออายุเมื่อไหร่ (โทเคนหมดอายุ = ส่งรายงานจากโปรแกรมไม่ได้ ตัวกลางตอบ 502)
   - คัดลอกโทเคนเก็บไว้ชั่วคราว (GitHub โชว์ครั้งเดียว) — **ห้ามวางลงไฟล์ใดในรีโป ห้ามส่งให้ใคร**
2. **สร้าง Worker** — เข้า dash.cloudflare.com (สมัครบัญชีฟรีถ้ายังไม่มี) → Workers & Pages → Create → สร้าง Worker เปล่า ตั้งชื่อ `k2-bug-relay` → Deploy
3. **วางโค้ด** — เปิด Worker ที่เพิ่งสร้าง → Edit code → ลบของเดิมออกทั้งหมด → วางเนื้อของไฟล์ `worker.js` ในโฟลเดอร์นี้ทั้งไฟล์ → Deploy
4. **ตั้งค่าสองช่อง** — หน้า Settings ของ Worker → Variables and Secrets → Add
   - ชนิด Text · ชื่อ `GITHUB_REPO` · ค่า `Nbcybg/Killian-Editor-V2`
   - ชนิด **Secret** · ชื่อ `GITHUB_TOKEN` · ค่า = โทเคนจากข้อ 1 → Deploy
5. **ตรวจว่าทำงาน** — เปิดที่อยู่ของ Worker (`https://k2-bug-relay.<ชื่อบัญชี>.workers.dev`) ในเบราว์เซอร์ ต้องได้ `{"ok":true,"service":"k2-bug-relay"}`
6. **บอกโปรแกรม** — ใส่ที่อยู่นั้นลง `BUG_RELAY_URL` ใน `src/bugs/bug-config.js` แล้ว build + ออกรุ่นใหม่
   (ช่อง `BUG_CONTACT` ในไฟล์เดียวกัน = "ทางที่กำหนด" อีกทางหนึ่งที่โชว์ในกล่องรายงาน)

ชื่อเมนูในหน้าเว็บของ Cloudflare/GitHub ขยับได้ตามเวลา — หลักคือ: Worker หนึ่งตัว · โค้ดจาก `worker.js` · ตัวแปร `GITHUB_REPO` · ตัวแปรลับ `GITHUB_TOKEN`

### ทางเลือก: ติดตั้งด้วยคำสั่ง (สำหรับคนที่มี Node.js)

```bash
cd tools/bug-relay
npx wrangler login
npx wrangler secret put GITHUB_TOKEN
npx wrangler deploy
```

ทางนี้ได้ตัวจำกัดจำนวนครั้งต่อ IP (`RATE` ใน `wrangler.toml`) มาด้วย — ทางหน้าเว็บไม่มี ถ้าถูกยิงก่อกวนค่อยเปิดทีหลังได้

## กันคนนอกเปิด Issue จากหน้าเว็บ

รีโปสาธารณะปิดปุ่ม "New issue" ถาวรไม่ได้ จึงกันสามชั้น:

| ชั้น | ไฟล์ | ผล |
|---|---|---|
| หน้า "New issue" ไม่มีแบบฟอร์มเปล่า | `.github/ISSUE_TEMPLATE/config.yml` | คนที่กดจากเว็บเห็นแค่คำอธิบายว่าให้รายงานจากโปรแกรม |
| ปิดอัตโนมัติ | `.github/workflows/issue-gate.yml` | Issue ที่คนนอกเปิดได้อยู่ดี ถูกติดป้าย `invalid` · ปิด · ล็อก ภายในไม่กี่วินาที |
| โปรแกรมไม่แสดง | `isTrustedAuthor()` ใน `src/bugs/bug-core.js` | กล่องสถานะแสดงเฉพาะ Issue ที่ผู้ดูแล (หรือตัวกลาง) เป็นคนเปิด |

สองไฟล์แรกเริ่มทำงานเมื่อถูก push ขึ้นกิ่งหลักของรีโป

## รายงานจาก "ทางที่กำหนด"

ทางที่กำหนดอีกทางหนึ่งคือ **อีเมล** — ใส่ที่อยู่ลง `BUG_CONTACT.label` ใน `src/bugs/bug-config.js` แล้วกล่องรายงานจะมีบรรทัด
"ถ้าส่งจากโปรแกรมไม่ได้ ให้คัดลอกรายงานแล้วส่งทาง <อีเมล>" · คลิกที่อยู่ = คัดลอกรายงาน + เปิดอีเมลใหม่ถึงที่อยู่นั้น (หัวเรื่องขึ้นต้น `[Killian 2]`)
ได้รับอีเมลแล้ว ผู้ดูแลเปิด Issue เองบน GitHub โดย **วางรายงานทั้งก้อน** — ท้ายรายงานมีบรรทัดกำกับรุ่น คอลัมน์ "พบในรุ่น" จึงขึ้นเอง
(ที่อยู่อีเมลนี้อยู่ในรีโปสาธารณะและโชว์ให้ผู้ใช้ทุกคน — ใช้ที่อยู่สำหรับรับรายงานโดยเฉพาะ)

รายงานที่ได้รับทางอื่น (อีเมล/กลุ่ม) ผู้ดูแลเปิด Issue เองบน GitHub ได้ตามปกติ — Issue ของผู้ดูแลขึ้นในโปรแกรมเสมอ
อยากให้คอลัมน์ "พบในรุ่น" ขึ้น ให้ติดป้าย `found:alpha.169` (หรือวางบรรทัด `Version: 2.0.0-alpha.169` ในเนื้อ)

## จัดการสถานะ (สิ่งที่ผู้ใช้เห็นในกล่อง "สถานะบั๊ก")

| ในโปรแกรม | บน GitHub |
|---|---|
| รอตรวจสอบ | Issue เปิดอยู่ ยังไม่มีป้ายสถานะ (รายงานจากโปรแกรมเข้ามาแบบนี้ พร้อมป้าย `from-app`) |
| ยืนยันแล้ว | ป้าย `bug` หรือ `confirmed` |
| กำลังแก้ไข | ป้าย `in progress` |
| ขอข้อมูลเพิ่ม | ป้าย `need info` |
| แก้ไขแล้ว | ปิด Issue (completed) |
| ไม่แก้ไข | ปิดแบบ not planned หรือป้าย `wontfix` |
| ซ้ำกับรายการอื่น | ป้าย `duplicate` |
| *(ไม่ขึ้นในโปรแกรม)* | ป้าย `hidden` · `spam` · `test` — ใช้ซ่อนรายงานทดสอบ/สแปมโดยไม่ต้องลบ Issue |
| **แก้ไขในรุ่น** | ตั้ง Milestone ของ Issue เป็นชื่อรุ่น (เช่น `2.0.0-alpha.170`) หรือป้าย `fixed:alpha.170` |

## สิ่งที่ตัวกลางตรวจ

หัวคำขอ `X-K2-Client` · ขนาด (หัวข้อ ≤ 200 · เนื้อ ≤ 20,000 อักขระ · คำขอ ≤ 64KB) · รูปแบบรุ่น · เวลาของคำขอ (±15 นาที) ·
บรรทัดกำกับรุ่นในเนื้อ · จำกัดจำนวนครั้งต่อ IP (ถ้าเปิด `RATE`) · ตัด `@ชื่อ` ไม่ให้แท็กคนอื่น

**สิ่งที่ตัวกลางทำไม่ได้**: พิสูจน์ว่าคำขอมาจากโปรแกรมจริง — ซอร์สของโปรแกรมเป็นสาธารณะ ใครอ่านซอร์สก็เลียนคำขอได้
จึงให้ทุกรายงานเข้ามาในสถานะ "รอตรวจสอบ" และคัดด้วยมือ · ถ้าถูกยิงก่อกวน: ลดเพดานใน `wrangler.toml` หรือปิด Worker ชั่วคราว
(โปรแกรมจะบอกผู้ใช้ว่าส่งไม่ได้และให้คัดลอกรายงานแทน)

## ทดสอบ

ตรรกะตรวจคำขอ (`validateReport` · `issuePayload`) ถูกทดสอบใน `test/bug-core.test.cjs`
โดยส่งคำขอที่โปรแกรมสร้างจริงเข้าไป — แก้รูปของคำขอฝั่งใดฝั่งหนึ่งแล้วอีกฝั่งไม่ตาม เทสแดง
